# معماری کشف صفحهٔ اصلی KuCafe

وضعیت: PR بازبینی بصری؛ بدون انتشار.

## مسئله و معماری محتوا

صفحهٔ قبلی قبل از نشان‌دادن مسیرهای کاربردی، Hero تصویری، آمار بزرگ و متن معرفی طولانی داشت. ساختار جدید ترتیب «نیاز → جست‌وجو → اعتماد → انتخاب» را پی می‌گیرد: جست‌وجوی کوتاه، سه مسیر سریع، تجربه‌های دارای نتیجه، دسته‌های واقعی منو، محله‌های فعال، پیشنهادهای قابل توضیح و سپس رویداد/تخفیف واقعی، CTA فشردهٔ کافه‌دار و FAQ. بخش نظرهای تأییدشده در PR وابستهٔ بعدی بین مسیرهای سریع و تجربه‌ها قرار می‌گیرد.

سه مقصد «همهٔ دسته‌ها» از Hubهای موجود `experienceHub`، `menuHub` و `districtHub` استفاده می‌کنند؛ Landing واسطهٔ تازه‌ای ساخته نشده است. HeroSearch هنوز فرم GET عادی به `/search` است و نگاشت جست‌وجو عوض نشده. «نزدیک من»، «الان باز» و انتخاب محله مسیرهای قبلی را حفظ کرده‌اند.

## قرارداد داده و رتبه‌بندی

- تجربه فقط وقتی نشان داده می‌شود که `candidateCount > 0` باشد.
- خوراکی فقط از Facet دارای مجموعهٔ واقعی می‌آید؛ قیمت نامعلوم با صفر یکی نیست.
- محله فقط وقتی حداقل یک مجموعهٔ معتبر دارد ظاهر می‌شود.
- رویداد از `listUpcomingPublicEvents` و تخفیف از `DiscountDiscovery` موجود می‌آید؛ بخش بی‌داده رندر نمی‌شود.
- پیشنهادها از `listPlaceCards(sort: quality)` موجود و یک مجموعهٔ محدود می‌آیند. لایهٔ کوچک انتخاب، نخست محله‌های متفاوت را ترجیح می‌دهد و برای هر کارت دلیل قابل اثباتِ «چند تجربهٔ تأییدشده»، «قیمت منو ثبت شده» یا «منوی دسته‌بندی‌شده» می‌سازد. یک نظر پنج‌ستاره برچسب «بهترین» نمی‌گیرد. جزئیات در `homeRecommendations.ts` و تست آن است.
- برای جلوگیری از N+1، همان Queryهای موجود صفحه به‌صورت موازی استفاده شده‌اند؛ هیچ منوی کامل برای Home بار نمی‌شود. سقف نامزدها `max(24, homeCardCount × 5)` و سقف نمایش ۴ کارت است.

## SEO و عملکرد

Canonical، Metadata، JSON-LD، FAQ و لینک‌های داخلی اصلی باقی‌اند. متن تکراری معرفی حذف شده ولی مسیرهای Methodology، صفحات محله، غذا، تجربه و کافه‌ها حفظ شده‌اند. کارت‌های پایین صفحه تصویر Lazy دارند. دادهٔ SSR همچنان عمومی و قابل خزش است.

اندازه‌گیری مرورگری قبل/بعد، ارتفاع صفحه، مختصات First Fold، خطای تصویر و Overflow در `var/qa/product-discovery/metrics.json` ثبت می‌شود. در ۳۹۰×۸۴۴، جست‌وجو از `y=379` به `y=242` و شروع اولین دسته از `y=1282` به `y=435` رسید. ارتفاع کل صفحه از ۶۵۹۸ به حدود ۴۳۰۹ پیکسل رسید؛ تعداد Sectionهای اصلی ۸ در هر دو حالت است، یعنی کاهش ارتفاع با حذف محتوا به‌صورت صوری ادعا نمی‌شود. Overflow و تصویر شکستهٔ قابل‌دیدن صفر بود. این اعداد از Dev در برابر Production خواندنی‌اند و ادعای Core Web Vitals Production نیستند. تصاویر واقعی در همان پوشه‌اند؛ اندازه‌گیری پس از PR نظرها تکرار می‌شود.

## محدودیت

PR این صفحه بدون Query نظرهای کاربران قابل بازبینی مستقل است. رتبه‌بندی و کارت‌های نظر تأییدشده، ابطال کش Moderation و Tracking مرتبط در PR وابسته انجام می‌شوند. هیچ داده، Migration یا تنظیم Production تغییر نمی‌کند.
