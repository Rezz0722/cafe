# انتخاب کافه‌ها برای اسکرپ و همگام‌سازی

## فهرست اجرا

- [x] انتخاب کافه قبل از اسکرپ، جست‌وجوی نام فارسی/نام منبع، انتخاب همه نتایج و پاک‌کردن انتخاب‌ها.
- [x] انتخاب مستقل از کافه‌های گزارش قبل از اعمال؛ کافه تازه نیز قابل انتخاب است.
- [x] محدودسازی اسکرپر پایتون و worker اعمال با source ID؛ انتخاب خالی هیچ‌وقت به معنی همه نیست.
- [x] کنترل Backend: مجوز مدیر، Origin، شناسه صحیح، تطابق فهرست، شناسه گزارش و جلوگیری از شروع همزمان.
- [x] تست واحد، Typecheck، بیلد، تست واقعی روی دیتابیس موقت و تست UI موبایل/دسکتاپ.
- [x] انتشار روی اصلی و dev و بررسی HTTP پس از انتشار.

## روش استفاده

در پنل مدیر → «عملیات» → «همگام‌سازی TopMenuMarket»:

۱. در «کدام کافه‌ها اسکرپ شوند؟» نام را جست‌وجو و کافه‌ها را تیک بزن. «انتخاب همهٔ نتایج» فقط نتایج جست‌وجوی فعلی را به انتخاب اضافه می‌کند. تغییر عبارت جست‌وجو انتخاب‌ها را پاک نمی‌کند.

۲. دکمه اسکرپ کافه‌های انتخاب‌شده را بزن. این مرحله فقط دریافت داده و ساخت گزارش است؛ دیتابیس منو تغییر نمی‌کند.

۳. بعد از آماده‌شدن گزارش، در «تغییرات کدام کافه‌ها اعمال شوند؟» انتخاب نهایی را انجام بده. برای اسکرپ انتخابی، همان انتخاب قبلی در گزارش پیش‌پر می‌شود و می‌توانی آن را محدودتر کنی.

۴. عبارت «همگام‌سازی کامل» را در کادر تأیید بنویس و «بکاپ و اعمال تغییرات انتخاب‌شده» را بزن. عبارت تأیید به معنی همگام‌سازی کامل منوی **همین کافه‌های انتخاب‌شده** است، نه همه کافه‌های سایت.

حالت «همهٔ کافه‌های منبع» برای کشف مجموعه‌های تازه و اسکرپ کامل باقی است؛ آن را باید صریحاً انتخاب کنی. «همهٔ کافه‌های همین گزارش» فقط محدوده گزارش جاری را اعمال می‌کند، نه خارج آن.

## قواعد ایمنی

- سایر کافه‌ها از ورودی transaction اعمال کنار گذاشته می‌شوند؛ قیمت، موجودی و آرشیو منو فقط برای انتخاب‌ها انجام می‌شود. آیتم دستی با source_id خالی آرشیو نمی‌شود.
- کافهٔ حذف‌شده از منبع یا شناسه نامعتبر به‌صورت خودکار به انتخاب همه تبدیل نمی‌شود؛ عملیات متوقف می‌شود.
- تداخل شناسه در کافه‌های انتخاب‌شده جلوی اعمال را می‌گیرد. تداخل کافه انتخاب‌نشده، اعمال کافه سالم را متوقف نمی‌کند؛ report انتخاب‌شده دوباره از دیتابیس بررسی می‌شود.
- شناسه گزارش ارسال می‌شود؛ اعمال از تب قدیمی روی گزارش تازه رد می‌شود.
- فایل انتخاب برای هر اجرا جدا و ثابت ذخیره می‌شود؛ وضعیت جاری با rename اتمیک نوشته می‌شود. فایل قفل شروع، دو درخواست همزمان را از راه‌اندازی همزمان worker بازمی‌دارد.
- بکاپ دیتابیس قبل از اعمال همچنان اجباری است. قیمت‌های واقعی در زمان توسعه این قابلیت خودکار اسکرپ یا اعمال نمی‌شوند.
- بازسازی facet و دانلود تصاویر پس از اعمال مانند قبل انجام می‌شوند؛ این‌ها نگهداری index/media هستند، نه اعمال قیمت کافه تیک‌نخورده.
- dev و اصلی فعلاً دیتابیس مشترک دارند؛ dev محیط ایزوله برای عملیات داده‌ای نیست.

فهرست دقیق تغییرات: `TOPMENU_SELECTIVE_SYNC_FILES.txt`.

## نتیجه تست و انتشار

- ۳۲۷ تست واحد موفق، شامل اعتبارسنجی انتخاب‌ها و جلوگیری از تفسیر انتخاب خالی به همه.
- بیلد نهایی Next.js و Typecheck مستقل موفق. شناسه بیلد: `n2u8SGw7xHSOmacrR6gax`.
- تست worker واقعی روی دیتابیس موقت مستقل: دریافت انتخابی و کامل، اعمال زیرمجموعه، تغییر قیمت، ایجاد کافه جدید با منوی کامل، آرشیو آیتم منبع حذف‌شده و حفظ آیتم دستی. رکورد کافه و منوی کافه انتخاب‌نشده دقیقاً بدون تغییر ماند.
- تست شروع همزمان دو درخواست: فقط یکی شروع شد؛ درخواست اعمال گزارش قدیمی رد شد.
- تست اسکرپر پایتون با منبع شبیه‌سازی‌شده: فقط منو و ساعت کافه‌های انتخاب‌شده دریافت شد؛ شناسه خالی، غلط یا ناموجود قبل از درخواست منو رد شد.
- Chromium در عرض‌های ۳۲۰، ۳۹۰ و ۱۴۴۰: انتخاب و جست‌وجو، حفظ انتخاب‌ها، payload دریافت/اعمال، حالت همه، کنترل انتخاب خالی، بدون overflow و خطای Runtime.
- تست API واقعی: عدم ورود، Origin نامعتبر، انتخاب خالی/غلط و گزارش قدیمی رد شدند؛ snapshot خراب پنل را از کار نینداخت و اعمال ناامن غیرفعال ماند.
- بررسی پس از انتشار روی `https://kucafe.ir/admin` و `https://dev.kucafe.ir/admin`، هر دو در عرض ۳۹۰ و ۱۴۴۰: چک‌باکس واقعی، حفظ انتخاب در جست‌وجو، ارسال فقط شناسه منتخب با رهگیری و جلوگیری از اجرای واقعی، غیرفعال‌بودن انتخاب خالی و رد آن در API واقعی. خطای JavaScript یا overflow ثبت نشد.
- پروژه دستور مستقل Lint/پیکربندی ESLint ندارد؛ `git diff --check` فایل‌های تغییرکرده موفق بود. این را معادل اجرای ESLint گزارش نمی‌کنیم.
- هیچ اسکرپ واقعی TopMenuMarket یا اعمال قیمت روی دیتابیس اصلی در این اجرا انجام نشده است؛ حساب‌های کوتاه‌عمر تست UI بعد از آزمایش حذف شدند.

Screenshotها در `var/qa/topmenu-selection/` هستند. تست Safari یا موبایل فیزیکی در این اجرا ادعا نمی‌شود؛ UI با Chromium شبیه‌سازی شده است.

## انتشار و بازگشت

انتشار در ۱۷ سپتامبر ۲۰۲۶ روی اصلی و dev انجام شد. هر دو همان شناسه بیلد بالا را دارند.

- اصلی: سورس و بیلد `/var/www/kucafe`؛ PM2 با نام `kucafe`، backend روی `127.0.0.1:3000`.
- dev: سورس و بیلد `/opt/kucafe`؛ systemd با نام `kucafe-dev`، backend روی `127.0.0.1:9091`.
- فقط فایل‌های manifest منتقل شدند؛ `.env.local`، state و اجراهای قبلی اسکرپ، کاربران، دیتابیس، تصاویر و schema بازنویسی نشدند.
- اصلی و dev پس از راه‌اندازی HTTP 200 دادند؛ www با 308 به دامنه اصلی هدایت می‌شود. worker MapLibre همچنان HTTP 200 و `text/javascript` دارد.
- هنگام راه‌اندازی مجدد فرایند تک‌نمونه اصلی، یک پاسخ موقت 503 ثبت شد؛ پس از Ready شدن سرویس، بررسی HTTP و UI هر دو موفق شدند. این روش reload در وضعیت فعلی تضمین zero-downtime نمی‌دهد.
- بکاپ سورس قبلی: `/var/backups/kucafe/topmenu-selective-source-before-20260917.tar.gz`.
- بیلد قبلی اصلی: `/var/www/kucafe/.next-before-selective-topmenu-20260917`؛ نسخه قبل dev نیز با safe-build در `/opt/kucafe/.next-previous` حفظ شده است.
- در صورت بازگشت، سورس قبلی و بیلد قبلی را با هم برگردان؛ worker اعمال یک اسکریپت سورس است، نه فقط بخشی از بیلد Next. PM2 را **از داخل `/var/www/kucafe`** reload کن؛ اجرای آن از cwd دیگر می‌تواند فرایند اصلی را به مسیر نادرست متصل کند.
- پس از تست، تعداد حساب موقت این آزمایش و دیتابیس‌های آزمایشی با نام اختصاصی هر دو صفر بود؛ سرور QA روی ۹۰۹۵ نیز متوقف شد.

ریسک باقی‌مانده: ارتباط با منبع واقعی در این اجرا آزمایش نشده است تا اسکرپ یا تغییر داده ناخواسته رخ ندهد. تست پایتون با پاسخ شبیه‌سازی‌شده و تست همگام‌سازی با worker واقعی روی دیتابیس مستقل انجام شده است. پاسخ خطا/تغییر API منبع واقعی همچنان باید در گزارش اجرای خودت بررسی شود.
