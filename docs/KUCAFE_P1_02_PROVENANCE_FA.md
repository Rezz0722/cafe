# P1-02 — معنای زمان و منشأ اطلاعات منو

وضعیت: طراحی پیش از Migration. این تغییر روی شاخهٔ مستقلِ وابسته به P1-01 آماده می‌شود؛ Production تا تأیید انتشار دست‌نخورده می‌ماند.

## نقص تأییدشده

TopMenu Apply در هر اجرا `place.last_verified_at` را به زمان Apply تغییر می‌دهد، حتی وقتی هیچ انسانی داده را تأیید نکرده و قیمت‌ها تغییر نکرده‌اند. صفحهٔ کافه وقتی زمان تغییر قیمتِ آیتم‌ها موجود نیست، از همین مقدار برای «آخرین به‌روزرسانی قیمت» استفاده می‌کند. بنابراین یک Sync می‌تواند به‌اشتباه تأیید یا تازگی قیمت را القا کند. `place.source` هم منشأ اولیهٔ رکورد است، نه منشأ تک‌تک فیلدهای منو پس از ویرایش پنل.

## قرارداد داده

- `last_verified_at`: فقط تأیید مستقل/انسانی مجموعه؛ TopMenu دیگر آن را نمی‌نویسد. مقدار تاریخی رکوردهای وارداتی دستکاری نمی‌شود، چون بدون Audit نمی‌توان همهٔ معانی قدیمی را به‌طور قطعی بازسازی کرد. هیچ مصرف‌کنندهٔ عمومی نباید آن را برای قیمت یا کافهٔ منبعی به‌عنوان تأیید به‌کار ببرد.
- `last_source_sync_at`: زمان اعمال موفق Snapshot خارجی، مستقل از تأیید. برای رکوردهای TopMenu موجود (`source='import'` و `source_id` موجود) از مقدار تاریخی `last_verified_at` فقط به‌عنوان **زمان تقریبی Sync قبلی** backfill می‌شود؛ این backfill ادعای تأیید نیست.
- `menu_item.price_updated_at`: آخرین تغییر **ثبت‌شده** در قیمت آیتم؛ نه زمان تأیید قیمت و نه زمان مشاهدهٔ دوبارهٔ قیمتِ بدون تغییر. نمایش عمومی باید این تفاوت را روشن کند. نبود آن با زمان Sync یا `last_verified_at` پر نمی‌شود.
- امتیاز تازگی فیلدی فقط از `provenance.observedAt` همان فیلد محاسبه می‌شود؛ زمان کلی مکان جای همهٔ فیلدهای فاقد شواهد را نمی‌گیرد.
- نشان‌های P1-01 تنها اثبات ویرایش انسانی مجازِ فیلد هستند؛ اثبات مالکیت تاریخی، تأیید همهٔ منو یا تأیید تک‌تک قیمت‌ها نیستند.

## انتشار و Rollback

Migration افزایشی و idempotent است؛ ستون قدیمی و داده‌های قیمت را حذف نمی‌کند. پیش از Deploy باید Backup معتبر و Migration آزمایشی، تست‌های واحد/Integration، Typecheck، Build و SSR smoke سبز باشند. Rollback کد: نسخهٔ قبلی به ستون جدید نیاز ندارد و ستون را می‌توان تا انتشار اصلاحی نگه داشت. حذف ستون فقط پس از ثبت/صدور داده‌های Sync جدید مجاز است؛ فایل rollback اختیاری آن را حذف می‌کند و زمان‌های Sync ثبت‌شده پس از Migration از بین می‌رود.

## محدودیت

برای داده‌های قدیمیِ بدون `source_id`، تشخیص منشأ دقیق فیلدها ممکن نیست. تا ثبت شواهد واقعی، UI فقط منشأ اولیهٔ رکورد و زمان تغییر ثبت‌شده را بیان می‌کند و ادعای «تأیید کافه‌دار» نمی‌سازد.
