# برنامهٔ جامع SEO و GEO کو کافه

آخرین بازبینی: ۱۴۰۵/۰۶/۲۱ — دامنهٔ کانونی: `https://kucafe.ir`

## به‌روزرسانی خط مبنا — ۱۴۰۵/۰۶/۲۵

- جست‌وجوی برند با فاصله، «کو کافه»، صفحهٔ اصلی را در نتیجهٔ اول نشان می‌دهد.
- جست‌وجوی بدون فاصله، «کوکافه»، با یک رقیب مستقیم به دامنهٔ `koocafe.ir`
  برخورد دارد؛ این رقیب نام دقیق بدون فاصله و پوشش سراسری بزرگ‌تری دارد. بنابراین
  این کوئری فقط مسئلهٔ فنی نیست و به تثبیت موجودیت برند و اعتبار بیرونی نیاز دارد.
- صفحات کافهٔ کو کافه در نتایج زندهٔ گوگل دیده می‌شوند؛ نمونهٔ صفحهٔ دژ کافه
  برای کوئری‌های مرتبط با منو و قیمت ظاهر شده است. یعنی مسیر crawl/index باز است.
- نام‌های جایگزین واقعی برند (`کوکافه`، `KuCafe` و `kucafe.ir`) به WebSite و
  Organization JSON-LD، صفحهٔ درباره و نمای ماشین‌خوان اضافه شدند.
- `/mashhad` از یک هاب صرفاً محله‌ای به صفحهٔ هدف «کافه‌های مشهد» با عنوان،
  H1، توضیح و راهنمای انتخاب داده‌محور ارتقا یافت.

### نقشهٔ کوئری به صفحهٔ کانونی

| خوشهٔ جست‌وجو | صفحهٔ هدف | وعدهٔ صفحه |
|---|---|---|
| کو کافه، KuCafe، کوکافه | `/` و `/about` | موجودیت و هویت برند |
| کافه مشهد، کافی‌شاپ مشهد | `/mashhad` | فهرست شهر، محله، نقشه، منو و قیمت |
| منوی کافه‌های مشهد | `/mashhad/menu` | دسته و خوراکی با قیمت واقعی |
| کافه سجاد/هاشمیه/وکیل‌آباد… | `/mashhad/{district}` | مجموعه‌های همان محله |
| پاستا/لاته/صبحانه در مشهد | `/dish/{slug}` و `/mashhad/menu/{facet}` | مقایسهٔ هم‌نوع و قیمت |
| منوی راموز و نام هر کافه | `/cafe/{slug}` | شعبه، منو، ساعت، مسیر و اعتماد داده |
| بهترین کافه مشهد | صفحهٔ بررسی‌شده‌ها، پس از دادهٔ کافی | انتخاب تحریریه با شواهد و تاریخ بازدید |

### حلقهٔ رشد هفتگی

1. خروجی Search Console در بازه‌های ۷ و ۲۸ روزه ثبت شود: query، page، impression،
   click، CTR و position.
2. کوئری‌های position 4–20 و impression بالا به صفحهٔ کانونی درست نگاشت شوند.
3. همان صفحه با دادهٔ واقعی، پاسخ کوتاه‌تر، عنوان بهتر و لینک داخلی تقویت شود.
4. URL اصلاح‌شده یک‌بار برای crawl ارسال شود؛ درخواست مکرر سرعت ایجاد نمی‌کند.
5. نتیجه پس از ۱۴ و ۲۸ روز با خط مبنا مقایسه شود؛ تغییر بی‌اثر برگردانده یا
   بازطراحی شود.
6. هر هفته حداقل یک دارایی منحصربه‌فرد قابل استناد ساخته شود: بررسی میدانی
   بلاگر، تغییرات قیمت، منوی تازه، یا گزارش محله؛ نه مقالهٔ عمومی بازنویسی‌شده.

## هدف و معیار موفقیت

هدف فنی، رساندن کنترل SEO در Lighthouse به بازهٔ ۹۵ تا ۱۰۰ و حذف خطاهای
خزش، ایندکس، canonical، دادهٔ ساخت‌یافته و تجربهٔ موبایل است. هدف کسب‌وکاری،
رشد ورودی ارگانیک با نیت‌های «کافه مشهد»، «منوی کافه X»، «قیمت Y در مشهد»،
«کافه در محله X» و «کافه نزدیک من» است.

امتیاز Lighthouse و رتبهٔ یک گوگل دو چیز متفاوت‌اند. امتیاز نزدیک ۱۰۰ قابل
مهندسی است، ولی رتبهٔ یک به رقبا، اعتبار دامنه، لینک‌های واقعی، رفتار کاربر و
زمان ایندکس نیز وابسته است و تضمین فنی ندارد. معیار درست، ترکیب امتیاز فنی با
impression، CTR، رتبهٔ کوئری، صفحات ایندکس‌شده و تبدیل بازدید به استفاده از
جست‌وجو/مسیریابی است.

## یافته‌های ممیزی اولیه

### نقاط قوت موجود

- HTTPS و ریدایرکت `www` به دامنهٔ کانونی فعال است.
- صفحهٔ هر کافه URL پایدار، title و description داده‌محور، canonical و
  `LocalBusiness`/`Restaurant` JSON-LD دارد.
- منوی کافه از خود کافه جدا شده و آیتم‌ها و Dishهای محبوب صفحهٔ مستقل دارند.
- صفحات محله و sitemap دیتابیس‌محور وجود دارند.
- صفحات خصوصی `noindex` هستند و صفحات جست‌وجو ترکیب‌های بی‌نهایت را وارد
  sitemap نمی‌کنند.
- محتوای اصلی صفحهٔ خانه و صفحات کافه سمت سرور رندر می‌شود.

### ضعف‌های مهمی که در فاز اول پیدا شد

1. پیام Hero قبلی («امروز کجا بریم؟») کاربرد دقیق محصول را در پنج ثانیهٔ اول
   توضیح نمی‌داد و کاربر نمی‌دانست نام کافه، محله یا آیتم منو قابل جست‌وجو است.
2. CTAهای بدون نیاز به تایپ — نزدیک من، الان باز، نقشه و محله — در اولین نمای
   صفحه سلسله‌مراتب مشخصی نداشتند.
3. ارزش اصلی کو کافه یعنی «منوی قابل جست‌وجو و مقایسهٔ قیمت» در صفحهٔ اول
   جایگاه کافی نداشت.
4. پیام کافه‌دار به «پروژهٔ مردمی/ساختهٔ جوون‌های مشهد» محدود شده بود و ارزش
   پنل، صفحهٔ اختصاصی و مدیریت منو را بیان نمی‌کرد.
5. لینک‌های دربارهٔ ما و تماس در فوتر به خود خانه برمی‌گشتند و مقصد معنایی
   مشخصی نداشتند.
6. صفحهٔ خانه JSON-LD مخصوص `Organization`، `WebSite`، `CollectionPage` و FAQ
   نداشت و تصویر کامل Open Graph هم تعریف نشده بود.
7. `favicon.ico` پاسخ ۴۰۴ می‌داد و icon/manifest صریح وجود نداشت.
8. هاب `/mashhad` با وجود اهمیت معماری، در sitemap نبود.
9. `/search` هم در robots مسدود و هم `noindex` بود؛ crawler نمی‌توانست دستور
   `noindex` را ببیند. robots فقط باید مسیر خصوصی را ببندد و صفحهٔ جست‌وجو
   خودش `noindex,follow` بماند.
10. دسترسی `OAI-SearchBot` و `ChatGPT-User` صریح نبود. تنظیم عمومی اجازه می‌داد،
    اما قاعدهٔ اختصاصی جلوی regression آینده را می‌گیرد.
11. صفحات دستهٔ منو فعلاً عمدتاً به `/search?f=...` می‌روند و به‌دلیل noindex
    لندینگ کانونی برای عباراتی مثل «صبحانه در مشهد» ندارند.
12. اعتماد و منشأ داده نیازمند صفحه‌های مستقل «روش جمع‌آوری و به‌روزرسانی»،
    «دربارهٔ کو کافه»، «حریم خصوصی» و «قواعد انتشار نظر» است.
13. خواندن session در layout ریشه همهٔ صفحات را dynamic و `private/no-cache`
    می‌کند؛ برای TTFB و استفادهٔ بهتر از cache باید در یک فاز مستقل جدا شود.
14. تصویرهای محیط واقعی برای تعداد زیادی از کافه‌ها کم است؛ این هم CTR و هم
    image search و اعتماد کاربر را محدود می‌کند.

## چک‌لیست انتشار هر تغییر

```bash
cd /opt/kucafe
npm run typecheck
npm test
npm run build
sudo systemctl restart kucafe-dev.service
npm run seo:smoke -- https://dev.kucafe.ir
npm run seo:crawl -- https://dev.kucafe.ir
```

پس از تأیید تصویری موبایل و دسکتاپ، نسخه به production منتقل می‌شود و همین تست
روی `https://kucafe.ir` دوباره اجرا خواهد شد. در Search Console باید URL Inspection
برای خانه، هاب محله، یک محله، یک Dish و یک کافهٔ کامل انجام شود.
