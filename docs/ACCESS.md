# دسترسی‌ها و راه‌اندازی

> این سند همان چیزی است که برای ورود و مدیریت سایت لازم داری.
> **در git هست، پس هیچ کلید یا رمزی داخلش ننویس.**

---

## ۱. اول از همه — امنیت

### کلیدی که لو رفت

فایل `SMS.ir _ برنامه نویسان.html` که ذخیره کرده بودی، یک کلید API را
به‌صورت متن ساده داخل خودش داشت (بخش AUTHORIZATION، مقدار `X-API-KEY`).

خبر خوب: آن کلید **نامعتبر است** — تست شد و جواب داد «کلید وب سرویس نامعتبر
است». یعنی قبلاً عوض شده. فایل هم حذف شد و `*.html` به `.gitignore` اضافه شد
تا دوباره تصادفی commit نشود.

> کلید عمداً اینجا نوشته نشده. هر رشته‌ای که در git بنویسی برای همیشه در
> تاریخچه می‌ماند — حتی اگر بعداً پاکش کنی.

دو عادت را عوض کن:

1. صفحه‌ی پنل را با «Save page as» ذخیره نکن؛ کلید داخل HTML می‌آید.
2. کلید را در چت، تیکت یا اسکرین‌شات نفرست.

### کلید فعلی

کلید فعال در `.env.local` است که **در git نیست** (چک شد). هیچ‌وقت:
- در `.env.example` نگذارش (آن فایل commit می‌شود)
- در کد hardcode نکن
- در تیکت/چت/اسکرین‌شات نفرست

اگر شک کردی لو رفته: پنل SMS.ir → برنامه‌نویسان → لیست کلیدهای API → کلید
جدید بساز و در `.env.local` جایگزین کن.

---

## ۲. راه‌اندازی محلی

```bash
cd C:\cafegard
cp .env.example .env.local     # اگر نداری
npm install
npm run dev                    # http://localhost:3000
```

`.env.local` از قبل ساخته شده با کلید SMS.ir و یک `SESSION_SECRET` تصادفی.

### حالت توسعه — پیامک ارسال نمی‌شود

```env
AUTH_DEV_MODE=true
```

با این تنظیم **هیچ پیامکی ارسال نمی‌شود** و کد ورود در ترمینالی که
`npm run dev` را اجرا کرده چاپ می‌شود:

```
  ┌─────────────────────────────────────────┐
  │  کد تأیید برای 09151234567              │
  │            48213                        │
  │  (AUTH_DEV_MODE — پیامکی ارسال نشد)     │
  └─────────────────────────────────────────┘
```

این پیش‌فرض است و عمدی: اعتبار پیامک پول واقعی است و یک حلقه‌ی تست در چند
دقیقه تمامش می‌کند. اعتبار فعلی حساب حدود **۱۶۵** است — کم.

---

## ۳. ادمین شدن

هیچ حساب پیش‌فرض یا رمز hardcode شده‌ای وجود ندارد. این عمدی است — حساب
پیش‌فرض در کد، اولین چیزی است که هک می‌شود.

شماره‌ات را در `.env.local` بگذار:

```env
ADMIN_PHONES=09151234567
```

چند نفر را با کاما جدا کن. بعد سرور را ری‌استارت کن و با همان شماره وارد شو —
نقش `admin` خودکار داده می‌شود.

> اگر شماره‌ای بعداً به این لیست اضافه شود، در ورود بعدی ارتقا می‌گیرد.
> ولی **حذف از لیست، دسترسی را پس نمی‌گیرد** — تنزل باید آگاهانه از پنل
> ادمین انجام شود، نه به‌عنوان اثر جانبی ویرایش یک فایل.

## ۴. سه پنل

| مسیر | برای چه کسی | دسترسی |
|---|---|---|
| `/profile` | هر کاربر واردشده | `customer` به بالا |
| `/admin/venue` | مالک کافه | `owner` یا `admin` |
| `/admin` | تیم داده / مدیر | فقط `admin` |
| `/admin/new` | ثبت کافه‌ی جدید | فقط `admin` |

هر سه `noindex` هستند و در `robots.txt` هم مسدودند.

### چطور کسی مالک کافه می‌شود

از پنل ادمین: بخش کاربران → به کاربر مالکیت یک `slug` بده. نقشش خودکار از
`customer` به `owner` ارتقا می‌گیرد و `/admin/venue` برایش باز می‌شود.

## ۵. راه‌اندازی پیامک واقعی

برای تولید، `AUTH_DEV_MODE=false` کن. بعد یکی از این دو روش:

### روش الف — قالب OTP (توصیه‌شده)

خط OTP فیلتر نمی‌شود و تحویلش سریع‌تر است.

1. پنل SMS.ir → **ارسال سریع** → **لیست قالب‌ها** → قالب جدید
2. متن قالب چیزی شبیه این:
   ```
   کافه‌گرد
   کد ورود شما: #CODE#
   ```
3. شناسه‌ی قالب را بردار و در `.env.local`:
   ```env
   SMSIR_TEMPLATE_ID=123456
   SMSIR_TEMPLATE_PARAM=CODE
   ```

### روش ب — خط عادی (موقت)

بدون ساختن قالب کار می‌کند. خطوط موجود حساب: `10002155613464` و
`30004505000017`.

```env
SMSIR_LINE_NUMBER=30004505000017
```

⚠️ برای OTP ایده‌آل نیست: ممکن است تأخیر بخورد یا فیلتر شود. برای شروع
قابل قبول است، ولی قالب را بساز.

## ۶. محافظت از اعتبار پیامک

هر درخواست کد، پول خرج می‌کند. سه لایه محدودیت فعال است:

| لایه | مقدار | چرا |
|---|---|---|
| فاصله بین دو درخواست یک شماره | ۹۰ ثانیه | جلوی اسپم دکمه |
| سقف هر شماره در ساعت | ۵ | جلوی آزار یک شماره |
| **سقف سراسری در ساعت** | ۶۰ | جلوی چرخاندن شماره‌ها |

لایه‌ی سوم مهم‌ترین است: بدون آن، مهاجم شماره عوض می‌کند و هر بار سهمیه‌ی
تازه می‌گیرد. اعداد در `src/core/auth/otpConfig.ts` قابل تنظیم‌اند — با اعتبار
واقعی‌ات تنظیمشان کن.

علاوه بر این:
- کد **هش‌شده** ذخیره می‌شود، نه خام
- بعد از ۵ تلاش غلط، کد می‌سوزد
- کد بعد از مصرف بلافاصله باطل می‌شود
- عمر کد ۲ دقیقه است

---

## ۷. نشست‌ها

کوکی `httpOnly` امضاشده با HMAC-SHA256، عمر ۳۰ روز.

- `httpOnly` یعنی جاوااسکریپت نمی‌بیندش — XSS نمی‌تواند بدزددش
- امضا یعنی اگر کسی `role` را در کوکی به `admin` عوض کند، رد می‌شود
- نقش در هر درخواست **از فایل کاربران** خوانده می‌شود نه از کوکی، پس تغییر
  نقش یا مسدودکردن بلافاصله اثر می‌کند

عوض‌کردن `SESSION_SECRET` همه‌ی نشست‌های فعال را باطل می‌کند — راه اضطراری
برای بیرون‌انداختن همه.

## ۸. داده‌ها روی دیسک

| فایل | محتوا | در git؟ |
|---|---|---|
| `src/data/places.generated.json` | ۱۰۰ کافه از import | ✅ بله |
| `src/data/places.custom.json` | کافه‌های افزوده‌شده از پنل | ❌ نه |
| `src/data/users.json` | کاربران و نقش‌ها | ❌ نه |

**بکاپ:** سه فایل اول را باید بکاپ بگیری. الان هیچ بکاپ خودکاری نیست.

⚠️ نوشتن روی فایل روی محیط serverless (مثل Vercel) کار نمی‌کند — فایل‌سیستم
فقط‌خواندنی است. روی VPS معمولی (آروان، لیارا، پارس‌پک) مشکلی نیست. مسیر
Postgres در [DATA_LAYER.md](DATA_LAYER.md).

## ۹. چه چیزی هنوز واقعی نیست

| بخش | وضعیت |
|---|---|
| ویرایش منو/عکس/ساعت در پنل مالک | state محلی — ذخیره نمی‌شود |
| نقشه | grid با پین، نه تایل واقعی (باید نشان یا بلد شود) |
| آپلود عکس | placeholder، فایلی ذخیره نمی‌شود |
| نظرات کاربران | فقط نمایش؛ ثبت نظر واقعی نیست |
| Postgres | شما و مهاجرت آماده، آداپتور نوشته نشده |
| بکاپ خودکار | ندارد |
| AI | عمداً ساخته نشده — فاز ۳ |
