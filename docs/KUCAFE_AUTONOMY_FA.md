# ارکستریشن توسعهٔ کو کافه — نسخهٔ ۲

## قرارداد اجرایی فعلی؛ جایگزین محدودیت research-only نسخهٔ اول

نسخهٔ دوم برای کارهای مصوب کد واقعی تولید می‌کند، بازبینی مستقل می‌گیرد، PR می‌سازد، CI میزبانی‌شدهٔ GitHub را منتظر می‌ماند، با حفاظت عادی ادغام می‌کند و انتشار دقیق همان SHA را روی سایت زنده تأیید می‌کند. ادغام به‌تنهایی پایان کار نیست.

`timer → controller → planner → code writer → independent reviewer → PR → hosted CI → normal merge → protected deploy → live verification → next task`

## کنسول زنده و پیام مدیر

داشبورد عمومی رویدادهای ساختاری واقعی کنترلر را از `activity.json` می‌خواند؛ در هر نوبت، شروع/پایان، تغییر وضعیت کار/پژوهش، شروع/پایان عامل و خالی‌شدن صف ثبت می‌شود. خروجی خام مدل، فرمان‌ها، توکن‌ها و پیام مدیر عمومی نمی‌شوند. فایل خصوصی `activity.jsonl` سقف ۱ MiB دارد و نمای عمومی آخرین ۸۰ رویداد است. پایان نوبت مساوی تغییر کد یا انتشار نیست.

`https://kucafe.ir/admin/autonomy` فقط با نشست مدیر واقعی و خارج از حالت «مشاهده به‌عنوان» در دسترس است. API همان نشست را برای GET/POST بررسی می‌کند، پاسخ‌ها `private, no-store` هستند، POST مبدأ هم‌دامنه و متن ۲ تا ۲۰۰۰ نویسه می‌خواهد و صف پیام محدود است. اپ تنها دو bind محدود دارد: snapshot عمومی فقط‌خواندنی و `/var/lib/kucafe-autonomy/owner-console` برای پیام‌ها؛ checkpoint، اعتبار Codex و GitHub داخل کانتینر نیستند.

پاسخ پیام هم‌زمان و ساختگی نیست: پیام پس از ثبت، در نوبت بعدی ناظر (با رعایت سهمیهٔ مدل) توسط عامل read-only پاسخ داده و در همان کنسول ظاهر می‌شود. پیام تازه صف کدنویسی مصوب را خودکار بزرگ نمی‌کند و دستور حذف، migration، پرداخت یا تغییر حفاظت GitHub به شمار نمی‌آید. این مرز باید در UI روشن بماند؛ برای توسعهٔ خودکار تسک تازه، تبدیل درخواست مالک به roadmap محدود و قابل‌تست یک کار مستقل است. وقتی دو کار مصوب تمام‌اند، ناظر صریحاً بیکاری صف را ثبت می‌کند؛ اجرای timer پیشرفت محصول نیست.

صف مصوب `scripts/autonomy/roadmap.json`: اصلاح باگ ترتیب جست‌وجو با GPS ذخیره‌شده؛ سپس جلوگیری از ورود مجدد چهار source ID خدماتی 162/248/711/731؛ ادامهٔ تحقیق ۱۷ پروندهٔ قبلی؛ و توقف صادقانهٔ پایلوت واقعی در نبود مشارکت مشتری، QR چاپی و توافق تجاری. وظایف جدید بدون دامنه، مسیر مجاز، معیار پذیرش و تطبیق checkpoint اضافه نمی‌شوند. صف محدود، کار بی‌نهایت اختراع نمی‌کند.

عامل‌ها shell/exec/apps/plugins ندارند، read-only هستند و فقط JSON فایل پیشنهادی می‌دهند. مدل فرمان اجرایی یا GitHub/DB credential دریافت نمی‌کند. کنترلر تغییر را با allowlist، سقف حجم و اضافه/حذف خطوط، نبود عملیات حساس و الزام تست کنترل می‌کند؛ بازبین به hash همان patch متصل است. کد مخزن عمومی با اعتبار ChatGPT روی worker مدل اجرا نمی‌شود؛ CI جدا و میزبانی‌شده است. API پولی جدید اضافه نشده است.

فقط PR خودش با HEAD دقیق بازبینی‌شده، verify و تمام checks موفق، پایهٔ production و mergeState پاک ادغام می‌شود. admin bypass و force-push وجود ندارند. اصلاح CI حداکثر سه تلاش با branch جدید است. شکست انتشار وابستگی را متوقف می‌کند؛ image rollback موجود به معنی DB migration rollback نیست. صف اولیه به تغییر pure محدود است: نه schema/auth/env/packages/workflows، نه import/DB write/purge، نه SMS یا خرید سرویس. تحقیق بدون شاهد معتبر تمام‌شده یا ویژگی تأییدشده اعلام نمی‌شود.

timer فعلی پنج دقیقه پس از پایان tick با حداکثر ۳۰ ثانیه تأخیر وضعیت را می‌خواند؛ تماس مدل هر پنج دقیقه نیست. سقف روزانه چهار چرخه مهندسی و چهار بسته تحقیق، سه تلاش هر تسک و ۴۰ دقیقه سرویس است. quota پیش از مراحل مدل خوانده می‌شود؛ مصرف primary≥۸۰٪ یا secondary≥۹۰٪ انتظار تا reset واقعی، telemetry نامعلوم توقف. زیر ۲GiB tick و زیر ۲٫۵GiB merge متوقف می‌شوند. پاک‌سازی Docker/media/backup خودکار نیست. انتظار بیش از ۲۴ ساعت workflow، نیازمند reconciliation ثبت می‌شود.

ارتقا با `upgrade.sh <protected-green-SHA>` فقط هنگام سرویس بیکار، با snapshot خصوصی نسخهٔ قبل و حفظ checkpoint انجام می‌شود. وضعیت مهندسی در `/var/lib/kucafe-autonomy/orchestration.json` جدا از پژوهش است. خواندن وضعیت: `node /opt/kucafe-autonomy/scripts/autonomy/orchestrator.mjs status`. توقف/PAUSE مشترک و unit commands نسخهٔ قبل معتبرند. Rollback کنترلر: توقف timer/service، بازگرداندن source/unit از `/var/lib/kucafe-autonomy/releases/<sha>`، daemon-reload و شروع timer؛ state را برای بررسی نگه دار. این کار محصول منتشرشده را rollback نمی‌کند.

وضعیت زنده: `http://45.159.115.116/kucafe-autonomy/status.json`؛ دانلود: `http://45.159.115.116/kucafe-autonomy/latest.zip`.

داشبورد فارسی و موبایل‌پذیر: `http://45.159.115.116/kucafe-autonomy/`؛ هر ۱۵ ثانیه در تب فعال checkpoint عمومی و رویدادهای ساختاری را می‌خواند. ناتمام‌بودن CI/انتشار، کمبود شاهد و انتظار اطلاعات مالک با موفقیت اشتباه نمی‌شوند. خطای شبکه آخرین داده را حفظ می‌کند و هشدار واضح دارد. UI عمومی فقط خواندنی است؛ دکمهٔ حذف/ادغام/دیپلوی ندارد و گفت‌وگو فقط در کنسول مدیر انجام می‌شود. با `publish-dashboard.sh <protected-reviewed-SHA>` فقط فایل‌های گزارش از GitHub روی Apache کپی می‌شوند، نه کد اپ یا DB. نسخهٔ قبلی UI در snapshot خصوصی حفظ می‌شود. این نشر دارایی گزارش مستقل از Deploy اپ است و موفقیت آن موفقیت انتشار اپ را اثبات نمی‌کند.

ارتقای مستقل ناظر می‌تواند پیش از بیلد Next انجام شود، فقط اگر SHA جاری protected، PR ادغام‌شده و CI موفق باشند و مقایسهٔ کامل با نسخهٔ منتشرشده ثابت کند تمام تغییرات محدود به `scripts/autonomy/` و همین راهنما هستند. تغییر اپ، CI، schema، public، مسیر نامعلوم یا مقایسهٔ ناقص مجاز نیست و باید انتشار دقیق اپ صبر کند. نصب ناظر با تست policy و بررسی unit خودش تأیید می‌شود؛ این تأیید جای موفقیت Deploy اپ را نمی‌گیرد.

تست‌ها: `node --test scripts/autonomy/*.test.mjs`، Typecheck، CI واقعی، systemd و اولین چرخهٔ کدنویسی/انتشار جداگانه گزارش می‌شوند. تا اولین انتشار خودکار معتبر، end-to-end تأییدشده ادعا نمی‌شود. Build سبز مساوی انتشار، کیفیت تحقیق یا رشد SEO نیست.

## سوابق نسخهٔ ۱ — متن زیر تاریخی است، نه قرارداد فعال نسخهٔ ۲

## دامنهٔ اولیه و صداقت وضعیت

این سامانه ناظر قطعی، پژوهشگر و بازبین مستقل دارد؛ دو عامل مدل به ترتیب اجرا می‌شوند تا مصرف و بار محدود بماند. اجرای زمان‌بندی‌شده مستقل از بازماندن گفت‌وگو است. ساختار روی Codex CLI موجود و ورود ChatGPT کار می‌کند؛ API پولی، حساب جایگزین یا مصرف خودکار credit/reset اضافه نمی‌کند. مدل پیش‌فرض CLI استفاده می‌شود؛ مدل یا تعرفهٔ خاصی تحمیل نشده است.

صف فعلی فقط ادامهٔ تحقیق ۱۷ پروندهٔ معلق فاز ۳ در چهار بسته است. سه ویژگی ثبت‌شدهٔ آدرس، ریوایو و نیوان دوباره اعمال نمی‌شوند. محتوای اینترنت دستور نیست؛ هویت شعبه، تاریخ واقعی و شاهد مستقیم لازم است. خروجی صفر پیشنهاد معتبر است و پایان بررسی مساوی تأیید ویژگی نیست. خانواده دسته‌بندی مجاز نیست.

پژوهشگر و بازبین read-only و بدون کانکتورهای تنظیمات شخصی اجرا می‌شوند. ناظر فقط فایل checkpoint خصوصی و PR اسناد از JSON بررسی‌شده می‌سازد. ساختار یا اطلاعات Production تغییر نمی‌کنند. هیچ حذف، archive، migration، پیام بیرونی، SMS، بیلد، دیپلوی، merge خودکار یا تغییر سیاست ایندکس در این صف مجاز نیست. حذف چهار رکورد خدماتی بعد از هفت روز هم خودکار نشده است.

این نسخه همهٔ توسعهٔ آینده را خودمختار نمی‌کند. کار برنامه‌نویسی/اعمال ویژگی باید ابتدا به صف صریحِ مجاز و قابل‌تست با مسیرهای مجاز و rollback اضافه شود؛ نبود اطلاعات مالک/مشتری/دسترسی، با حدس جایگزین نمی‌شود. PRها از CI معمول و حفاظت production عبور می‌کنند. ناظر اختیار دورزدن حفاظت GitHub ندارد.

## اجرا و محدودیت‌ها

ابزارهای shell_tool و unified_exec در هر عامل صریحاً غیرفعال هستند؛ یک اجرای واقعیِ بررسی ابزار، نبود ابزار shell/exec_command را در Codex 0.160.0 نشان داد. مجوز read-only و ProtectSystem دفاع دوم هستند، نه جایگزین حذف ابزار shell. ابزارهای وب و قابلیت‌های دیگر CLI باید پس از ارتقای نسخه دوباره بررسی شوند. تعداد search/open محدودیت دستوری است؛ سقف زمان، تلاش و چرخه روزانه در ناظر اعمال می‌شود. شاهد قدیمی‌تر از ۹۰ روز یا تاریخ آینده اجازهٔ claim ندارد.

خروجی موفق پژوهشگر و بازبین جداگانه ذخیره و پس از محدودیت مصرف از همان مرحله ادامه داده می‌شوند. خرابی بررسی HTTP، تحقیق موفق را دوباره اجرا نمی‌کند. گزارش وضعیت عمومی فقط شناسه بسته، تعداد ادعا، وضعیت و لینک PR دارد؛ متن مدل یا اسرار در آن نیست. آدرس ثابت ZIP وضعیت: `http://45.159.115.116/kucafe-autonomy/latest.zip` پس از نصب.

- systemd timer پس از بوت و سپس پنج دقیقه پس از پایان سرویس، با حداکثر ۳۰ ثانیه jitter یک tick اجرا می‌کند؛ هر tick الزاماً کار مدل نیست. صف مهندسی حداکثر چهار چرخه و صف پژوهش حداکثر چهار بسته در روز تقویمی تهران دارد؛ سقف سرویس مشترک ۴۰ دقیقه است. قفل flock و checkpoint حفظ می‌شوند.
- قبل از کار و پیش از بازبین، `account/rateLimits/read` خوانده می‌شود. ذخیره/انتشار raw پاسخ، شناسه حساب یا credit ممنوع است. رسیدن مصرف primary به ۸۰٪ یا secondary به ۹۰٪ باعث توقف با زمان reset واقعی و حاشیه ایمنی می‌شود. telemetry نامعلوم: توقف یک ساعت، نه حدس یا دورزدن محدودیت. پنجره حساب فعلی ۵ساعته و هفتگی مشاهده شده است؛ اعداد پنجره در کد ثابت نشده‌اند.
- کم‌تر از ۲GiB فضای آزاد: توقف مدل؛ پیش از هر tick یک سرویس مستقل منابع اجرا می‌شود. فقط کش قابل‌بازسازی KuCafe شامل snapshot کامپایل Next با فرمان دقیق و برگ‌های غیرمشترکِ متصل به marker اختصاصی DEPLOYMENT_ID قابل حذف‌اند؛ نه تصاویر نهایی، volume، مدیا، بکاپ یا کش dependency. قفل‌های fetch/deploy و تشخیص builder فعال مانع تداخل می‌شوند؛ هدف ۴GiB و حداکثر ۳۲ رکورد در هر اجرا است. عامل مدل همچنان به Docker socket دسترسی ندارد. اگر کش مجاز کافی نباشد، توقف با علت صریح حفظ می‌شود؛ تضمین ظرفیت نامحدود نیست.
- ناظر checkpoint را بعد از مراحل می‌نویسد. قطع اجرای مدل، بار بعد با تلاش محدود از سر گرفته می‌شود؛ خروجی ناقص موفقیت نیست. تکرار نشر GitHub پس از خطای مبهم ممنوع و نیازمند تطبیق commit/branch ثبت‌شده است.
- صف خالی/نیازمند شاهد به معنی توقف مصرف مدل است؛ اجرای بعدی بدون تماس مدل خارج می‌شود. صف تغییرکرده بدون تطبیق hash حالت قبلی اجرا نمی‌شود.
- گزارش‌های خام و خروجی مدل خصوصی هستند و خودکار به webroot کپی نمی‌شوند. لینک دانلود گزارش اپراتور شامل فایل‌های allowlist و بدون secrets تهیه می‌شود. رمز و فایل XLSX خصوصی وارد PR نمی‌شود. فیلتر secrets و read-only دفاع کامل در برابر استخراج اسرار نیستند؛ این نسخه باید فقط صف تحقیق کم‌ریسک را اجرا کند، نه وظایف با اختیار Production.

## نصب از GitHub و توقف

پس از CI سبز و merge عادی، فقط فایل‌های مسیر `scripts/autonomy` و dossier ورودی از SHA دقیق protected production در `/opt/kucafe-autonomy` نصب می‌شوند؛ شاخهٔ در حال توسعه نباید به سرویس دائمی بدل شود. فایل‌های service/timer با `systemd-analyze verify` بررسی و با نام جدید نصب می‌شوند؛ سرویس‌های اپ، runner و Apache تغییر نمی‌کنند. checkpoint در `/var/lib/kucafe-autonomy` با دسترسی 0700 است. binaryهای لازم: node، codex، curl، gh، flock. Codex 0.160.0 و ورود ChatGPT پیش از نصب بررسی شده‌اند.

وضعیت: `node /opt/kucafe-autonomy/scripts/autonomy/supervisor.mjs status`

توقف زمان‌بندی: `systemctl disable --now kucafe-autonomy.timer`

توقف اجرای جاری: `systemctl stop kucafe-autonomy.service` (همهٔ فرزندان در control-group متوقف می‌شوند).

pause پایدار: فرمان `pause`؛ ازسرگیری: فرمان `resume` پس از بررسی علت. PAUSE فایل اضطراری است که در صورت وجود در stateDir هیچ عامل جدیدی شروع نمی‌شود. تغییر حالت هم‌زمان با tick باید بعد از توقف سرویس/با همان flock انجام شود.

Rollback: timer و سرویس را متوقف کن؛ فایل‌های پروژه/دیتابیس اصلاً توسط این صف تغییر نمی‌کنند. وضعیت خصوصی را برای تشخیص حفظ کن. نصب نسخه قبلی فقط از SHA بررسی‌شده؛ hash صف باید با checkpoint سازگار باشد.
