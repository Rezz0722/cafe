# اصلاح پاپ‌آپ، مقایسه قیمت، نظردهی و نقشه

این تغییر در قالب مشترک صفحه کافه اجرا می‌شود، نه فقط راموز.

## فهرست کار و پذیرش

- [x] مقایسه قیمت: لودینگ حبابی آبی/بنفش ۲٫۴ ثانیه، نتیجه انیمیشنی مرکزی، مقایسه با نمونه کافی شهر و بدون ادعای تحلیل زنده AI.
- [x] دیالوگ‌های مشترک: وسط صفحه، اسکرول داخلی، بستن، Escape، Back سریع و آزادشدن قفل اسکرول.
- [x] نظردهی: دکمه شروع، سه مرحله، انتخاب چند سفارش، تاریخ سریع شمسی، جزئیات اختیاری، خطا و تأیید نهایی؛ حفظ سفارش و امتیازهای تفکیکی هنگام ویرایش.
- [x] رنگ منو در نوار پایین هم‌رنگ باقی دکمه‌ها.
- [x] انتخاب مسیریابی مرکزی و حذف عبارت «دقیق‌تر در ایران».
- [x] نقشه: نمایش موقعیت قبل از تمام لایه‌ها، وضعیت جزئیات غیرمسدودکننده، لغو درخواست هنگام خروج و نمای دوبعدی جایگزین برای شکست راه‌اندازی یا نبود WebGL.
- [x] Build، Typecheck، تست‌های واحد، موبایل و دسکتاپ و انتشار امن روی اصلی و dev.

## علل شناسایی‌شده

ریست `* { margin: 0 }` حاشیه خودکار native dialog را حذف می‌کرد؛ پنجره در بالا قرار می‌گرفت. در سطح مشترک و کامپوننت دیالوگ رفع شد.

مقایسه قبلی صرفاً چند گزینه ارزان‌تر را نشان می‌داد، نه مقایسه واقعی چند خوراکی. اکنون قیمت شروع در همین کافه، میانه شهر و تعداد مجموعه‌های نمونه در کنار هم دیده می‌شوند. نمونه‌های ناکافی و نسبت‌های بسیار مشکوک نمایش داده نمی‌شوند؛ تفاوت سایز و افزودنی صریح است.

در بررسی HTTPS اصلی، worker، shared module و GeoJSONها ۲۰۰ بودند. رندر MapLibre در محیط QA سازگار موفق بود، اما تست بعدی روی اصلی نبود WebGL2 در مرورگر تست را آشکار کرد. MapLibre ۶ به WebGL2 نیاز دارد؛ مطابق [مستندات رسمی](https://maplibre.org/maplibre-gl-js/docs/guides/v5-to-v6-migration-guide/)، این موضوع مستقل از MIME است. برای نبود WebGL یا شکست راه‌اندازی، نمای دوبعدی Leaflet ۱٫۹٫۴ به‌صورت lazy از همان GeoJSON محلی بار می‌شود؛ به CDN، tile server یا کلید خارجی وابسته نیست. موقعیت مجموعه‌ها قبل از جزئیات در دسترس است؛ خطای جزئیات مانع استفاده یا اسکرول نمی‌شود. فایل MapLibre worker تغییر نکرده است.

ویرایش نظر قبلاً امتیازهای تفکیکی ذخیره‌شده را پیش‌پر نمی‌کرد و ممکن بود آن‌ها را پاک کند؛ خواندن این امتیازها از Backend و پیش‌پرکردن فرم یکپارچه شد.

## محدوده و محدودیت

لودینگ مقایسه یک گذار بصری روی داده ازپیش‌خوانده‌شده است، نه درخواست تحلیل AI. برای reduced-motion مکث و حرکت غیرضروری حذف می‌شوند. داده کم کافی نیست و نتیجه ساختگی نمایش داده نمی‌شود.

منو و گالری ذاتاً تمام‌صفحه‌اند؛ پنجره‌های اطلاعات، مقایسه، نظر و انتخاب نقشه مرکز viewport قرار می‌گیرند.

Safari طبق درخواست قبلی در این تست نیست؛ شبیه‌سازی Chromium جای دستگاه فیزیکی نیست. Lint مستقل در پروژه پیکربندی نشده است.

بکاپ پیش از انتشار: `/var/backups/kucafe/kucafe-no-media-20260917T122538Z.tar.gz` همراه SHA256؛ شامل سورس و دیتابیس نسخه قبل است، نه مدیای اصلی. مدل داده، قیمت پایه، کاربران و اطلاعات واقعی در این تسک مهاجرت یا بازنویسی نمی‌شوند.

## نتیجه تست و انتشار

- تست‌های واحد: ۳۲۳ موفق، صفر خطا.
- Typecheck موفق؛ بیلد مرحله‌ای نهایی موفق. اولین بیلد به‌دلیل نقش اشتباه در fixture تست رد شد و نقش صحیح `customer` جایگزین شد.
- UI: عرض‌های ۳۲۰، ۳۹۰، ۴۳۰ و ۱۴۴۰ موفق؛ اندازه‌گیری مرکز هر پنجره، Back سریع در لودینگ و پس از نتیجه، آزادشدن scroll lock، منو و دسته‌ها، نگهداری سفارش هنگام تغییر Query و تاریخ شمسی.
- تست ثبت واقعی روی رکورد موقت: دوبار لمس فقط یک نظر، ذخیره تاریخ، ارتباط سفارش با نظر، موفقیت واضح، شروع مراجعه تازه، حفظ امتیاز غذا و سفارش هنگام ویرایش. fixture در پایان حذف شد.
- در تست مرحله‌ها، تبدیل DOM دکمه «ادامه» به «ثبت» می‌توانست ثبت زودهنگام ایجاد کند؛ کلیدهای مستقل DOM رفعش کردند. تست پذیرش اکنون صریحاً نبودن ثبت هنگام جابه‌جایی مراحل را می‌سنجد. یک نظر متعلق به آزمون موقت حذف شد و امتیاز همان مجموعه با نظرات واقعی بازحساب شد.
- نقشه روی صفحه کافه، ورود از نوار نقشه صفحه اصلی و Search Map موفق؛ worker و shared module MIME جاوااسکریپت صحیح، نشانگر و نقشه رندر، بدون console error و قفل اسکرول. با تأخیر عمدی ۹ ثانیه‌ای GeoJSON نیز نشان مکان پیش از تکمیل داده قابل استفاده بود.
- تست مرورگر با Chromium کامل و WebGL نرم‌افزاری مخصوص QA روی VPS اجرا شد؛ Headless Shell قدیمی در ایجاد صفحه گیر می‌کرد. تنظیم نرم‌افزاری QA هیچ تغییری در امنیت یا مرورگر کاربران ایجاد نمی‌کند.

## نتیجه انتشار — ۱۷ سپتامبر ۲۰۲۶

اصلی و dev از خروجی بیلد یکسان `7knwqbJomMk4SGBnn4zq_` استفاده می‌کنند. PM2 اصلی با cwd صحیح `/var/www/kucafe` آنلاین است و سرویس `kucafe-dev` فعال است. هر دو دامنه HTTP ۲۰۰ دارند. دیتابیس، کاربران واقعی، قیمت‌ها و تصاویر آپلودشده جایگزین یا مهاجرت نشده‌اند. فقط فایل‌های فهرست `CAFE_DIALOG_REFINEMENT_FILES.txt` همگام شدند؛ تغییرات نامرتبط worktree حفظ شدند.

- تست Chromium روی خود `https://kucafe.ir`: نقشه راموز، ورود به نقشه از صفحه اصلی و Search Map موفق؛ صفر خطای Console/Pageerror، بدون قفل اسکرول.
- تست عمدی نبود WebGL: نقشه دوبعدی محلی، نشانگر مجموعه و بزرگ‌نمایی موفق. تست تأخیر ۹ ثانیه‌ای داده: موقعیت پیش از تکمیل جزئیات قابل استفاده است.

- کنترل فنی SEO موفق؛ ۶۴ لینک داخلی خانه سالم و Search همچنان noindex است.
- هر چهار `.mjs` عمومی، نسخه‌دار و بدون نسخه، هم از localhost:3000 و هم از HTTPS اصلی: HTTP ۲۰۰ و `text/javascript`.
- یک ۴۰۴ موجود برای `/favicon.ico` هنگام دریافت زودهنگام آیکون مرورگر شناسایی شد. بسته ICO از PNG فعلی برند بدون تغییر پیکسل‌ها ساخته شد؛ اکنون HTTP ۲۰۰ و `image/x-icon`. تولید آن در postinstall و prebuild ثبت شده است.

### لایه سرو فایل‌های ماژول

HTTPS اصلی `/maplibre/` مستقیماً از Alias در `/etc/httpd/conf/extra/kucafe-tls.conf` به `/var/www/kucafe/public/maplibre/` می‌رود و از ProxyPass مستثناست. Apache `AddType text/javascript .mjs` دارد. localhost مستقیماً Next است و header صریح در `next.config.mjs` دارد. DNS بررسی‌شده به همین سرور می‌رسد؛ در مسیر بررسی‌شده CDN دیگری مشاهده نشد. worker اصلی MapLibre بدون ویرایش باقی مانده است.

### فایل‌ها و ریسک‌های باقی‌مانده

بخش‌های تغییرکرده: صفحه مشترک کافه و استایل آن، دیالوگ مشترک، فرم نظر، مسیریابی، نوار موبایل، نقشه و adapter دوبعدی، خواندن امتیازهای نظر، تنظیم MIME، تولید favicon و تست‌های پذیرش. فهرست دقیق فایل‌ها کنار همین گزارش است.

Safari مطابق درخواست قبلی اجرا نشده و دستگاه فیزیکی Android/iOS در اختیار تست نبوده است. نتیجه موبایل، شبیه‌سازی در Chromium است. Lint مستقل پروژه وجود ندارد؛ Build و Typecheck موفق‌اند. نمای دوبعدی عمداً جزئیات سه‌بعدی ساختمان را ندارد؛ نشانگر، خیابان، محله، زوم و موقعیت محلی را حفظ می‌کند. تست عمومی اولیه یک ۴۰۴ favicon را پیدا کرد؛ رفع و تست کامل دوباره موفق شد. نخستین انتخاب‌گر تست Leaflet به pane بدون ابعاد نگاه می‌کرد؛ به کانتینر قابل مشاهده اصلاح شد.

نکته محیطی موجود: در این سرور dev و اصلی دیتابیس مشترک دارند؛ dev محیط ایزوله برای تغییر داده واقعی نیست. همه fixtureهای این تست پاک شدند؛ شمارش نهایی کاربر، نظر و کافه موقت آزمون صفر است. تصاویر جدید آپلودشده اصلی که در dev نبودند، فقط با کپی فایل‌های مفقود و بدون حذف یا بازنویسی فایل موجود همگام شدند. جداکردن دیتابیس و چرخه رسانه dev یک کار معماری مستقل است و در این تسک اجرا نشده است.

### بازگشت نسخه

خروجی قبلی اصلی در `/var/www/kucafe/.next-before-map-fallback-20260917` حفظ شده است؛ خروجی قبل از کل بازنگری دیالوگ‌ها نیز در `/var/www/kucafe/.next-before-dialog-refinement-20260917` باقی است. سورس قبل از افزودن fallback در `/var/backups/kucafe/dialog-map-source-before-fallback-20260917.tar.gz` نگهداری می‌شود. این‌ها حذف نشده‌اند. برای rollback، release معیوب را به نام جدا منتقل کنید، خروجی قبلی را به `.next` برگردانید و **از cwd `/var/www/kucafe`** PM2 را reload کنید؛ سپس HTTP، فایل‌های static و صفحه کافه را دوباره تست کنید. PM2 فعلی تک‌پردازه است؛ reload ممکن است چند ثانیه پاسخ موقت ۵۰۳ داشته باشد، بنابراین انتشار ادعای zero-downtime ندارد.
