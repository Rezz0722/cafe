# ثبت کنترل‌شدهٔ مرور دوم

تصمیم تحریریه: فقط شناسه‌های ۲۱۹ (آدرس) و ۲۸۴ (نیوان)، ویژگی `open_late` با مقدار **۱ / نامزد** و منبع `editorial`. ساعت دقیق امروز، کیفیت تجربه یا بازبودن هر شب تا ۲/۴ صبح تضمین نمی‌شود. پنج پروندهٔ hold هیچ تغییری دریافت نمی‌کنند؛ دادهٔ نامعلوم صفر نمی‌شود.

شواهد و محدودیت‌ها: `KUCAFE_EXPERIENCE_REVIEW2_20261007.json`؛ خط مبنا: `KUCAFE_EXPERIENCE_BATCH_01_20261007.json`. بسته‌های تحقیق تاریخچه هستند، نه ادعای ثبت موفق در Production. نتیجهٔ واقعی اجرا جداگانه گزارش می‌شود.

اسکریپت `scripts/apply-experience-batch1.ts` به‌صورت پیش‌فرض dry-run است. اجرا فقط از maintenance image منتشرشده از شاخهٔ محافظت‌شده، با شناسهٔ ادمین واقعیِ فعال و بکاپ خصوصی معتبر مجاز است. اکانت/سشن جدید ساخته نمی‌شود؛ actorLabel صریحاً maintenance است، نه ادعای ورود انسانی.

این بسته فقط تا پایان نوامبر ۲۰۲۶ قابل استفاده است؛ سپس اسکریپت با خطای نیاز به بازبینی تازه متوقف می‌شود. CI آینده انقضای بسته را به‌عنوان رد صحیحِ عملیات تست می‌کند، نه شکست تغییرات نامرتبط پروژه.

قفل تراکنشی هر دو کافه، کنترل slug/آدرس/revision/انتشار و مقایسهٔ تمام ویژگی‌های قبلی، سپس افزودن فقط دو ویژگی با API مدیریتی موجود. عملیات یک تراکنش است؛ تعارض باعث rollback کامل می‌شود. retry فقط با مقدار و audit همین بسته مجاز است؛ هیچ ویژگی موجود بازنویسی نمی‌شود. URL شواهد در evidenceNote audit ذخیره می‌شود. مقدار confidence=75 طبق سیاست فعلی editorial است، نه احتمال آماری یا AI score. verifiedAt زمان بازبینی تحریریه است، نه تاریخ انتشار منبع یا تأیید مالک.

API موجود شاخص‌های مشتق قیمت/کیفیت کافه را بازمحاسبه می‌کند، ولی قیمت خام آیتم‌ها، منو و تصاویر تغییر نمی‌کنند. هیچ migration، دستهٔ جدید، UI یا سیاست index تغییر نمی‌کند.

Rollback داده: فقط اگر دو رکورد و audit همچنان دقیقاً به این اجرای بسته تعلق دارند، حذف همین دو `open_late` با مسیر مدیریتی و audit جدید؛ دادهٔ قدیمی desserts دست‌نخورده بماند. بازگرداندن کل دیتابیس برای این دو تغییر مناسب نیست. اگر ویرایش جدیدتری وجود دارد، rollback خودکار ممنوع و نیازمند بررسی است.
