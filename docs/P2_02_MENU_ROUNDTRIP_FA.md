# P2-02 — ورود کنترل‌شدهٔ خروجی منو

## دامنه و تصمیم معماری

خروجی JSON نسخهٔ ۱ و CSV نه‌ستونهٔ P1-03 بدون تغییر باقی می‌مانند. مسیر Import سادهٔ سه‌ستونه نیز دست‌نخورده است. مسیر جدید فقط `create-only / skip existing` دارد و روی سرویس‌های موجود مدیریت منو، RBAC، Revision، Audit و Cache سوار می‌شود. هیچ ID داخلی یا `publicId` خارجی برای نوشتن مستقیم به کار نمی‌رود؛ `publicId` فقط پس از تطبیق شعبه می‌تواند نشانهٔ تعارض باشد.

## ناورداها

- بارگذاری و Preview بدون Write؛ Apply فقط با توکن HMAC ده‌دقیقه‌ای، نقش زنده، قفل Revision شعبه و تراکنش.
- نام نرمال‌شدهٔ دسته/آیتم در همان شعبه برای تشخیص تکرار استفاده می‌شود؛ موارد مبهم، تکراری یا قرنطینه‌شده Fail Closed هستند.
- قیمت‌ها تومان‌اند؛ `null` و صفر جدا می‌مانند. هیچ زمان تاریخی واردشده از فایل به‌عنوان تأیید انسانی پذیرفته نمی‌شود؛ آیتم واردشده `price_updated_at` نامعلوم دارد.
- JSON سایز، موجودی، آرشیو، ویژه‌بودن و خروج از آمار قیمت را حفظ می‌کند. CSV فاقد publicId، نشان ویژه، منشأ، تاریخ قیمت و تفکیک کامل موجودی آیتم/سایز است؛ پس CSV فقط بازیابی متن/قیمت/سایز/وضعیت‌های قابل‌استنتاج است، نه Round-trip بی‌اتلاف. اگر همهٔ ردیف‌های سایز «ناموجود» باشند ولی قیمت پایه مثبت بماند، منشأ وضعیت مبهم است و فایل رد می‌شود؛ JSON را استفاده کنید. دسته‌های خالی JSON در این نسخه وارد نمی‌شوند.
- لینک تصویر صرفاً در Preview گزارش می‌شود؛ باینری/Hotlink خودکار وارد Media Store نمی‌شود.
- سقف فایل و تعداد آیتم و سقف هر Apply، بار DB و Payload را محدود می‌کند. Apply تکراری با Revision قدیمی یا نام‌های ایجادشده متوقف می‌شود. Cache فقط پس از Commit تازه می‌شود.

## ریسک و آزمون

در JSON، قیمت پایهٔ چندسایزی باید با کمترین سایز موجود سازگار باشد؛ ناسازگاری Conflict است. در CSV، قیمت پایهٔ تکراری آیتم و سطرهای سایز باید سازگار باشند. تست‌های parser، فایل خراب/نسخه/واحد نامعتبر، فرمول، اندازه، نام تکراری و JSON ناامن؛ Integration با MariaDB دورریختنی برای Export→Preview→Apply→Export، تکرار، نقش و شعبه بیگانه، Revision، Rollback خطا، Variant/Archive/Zero/Unknown و Timestamp لازم‌اند. آزمون واقعی Excel در پایلوت باقی می‌ماند.
