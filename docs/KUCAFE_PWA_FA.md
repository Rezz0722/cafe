## روش نصب

صفحه `https://kucafe.ir/install` از شروع سریع صفحه اصلی و فوتر در دسترس است.

### اندروید

در Chrome سایت را باز کن. وقتی مرورگر قابلیت نصب را آماده کند، «نصب کوکافه» در صفحه نصب فعال می‌شود. در غیر این صورت منوی سه‌نقطه مرورگر → Install app یا Add to Home screen → تأیید. نوع نصب بسته به مرورگر و گوشی می‌تواند WebAPK یا میان‌بر باشد؛ نصب APK ناشناس لازم نیست.

### آیفون

در Safari صفحه نصب را باز کن → Share → Add to Home Screen → در صورت وجود Open as Web App را روشن کن → Add. سایت نمی‌تواند پنجره نصب خودکار آیفون را فراخوانی کند. جای Share در نسخه‌ها و تنظیمات مختلف Safari متفاوت است. ممکن است در اولین بازکردن اپ، ورود مجدد با همان حساب سایت لازم باشد؛ PWA حساب یا دیتابیس جدا ندارد.

اگر سایت داخل مرورگر اینستاگرام/تلگرام یا اپ دیگری باز شده، ابتدا از منوی آن اپ در مرورگر اصلی باز کن. رفتار دقیق این منو به اپ بستگی دارد.

## معماری و قواعد ایمنی

- `src/app/manifest.ts`: ID پایدار `/`، scope و start_url ریشه، standalone، آیکون ۱۹۲ و ۵۱۲ و maskable، زبان فارسی/RTL و shortcut کشف/منو/پروفایل.
- لینک manifest و متای Apple به‌صورت ثابت در `<head>` ریشه قرار دارند؛ متادیتای استریم‌شدهٔ Next.js نباید نصب را به لینک داخل body وابسته کند. API فایل manifest ممکن است لینک همسان دیگری داخل body تولید کند؛ تنها لینک اصلی head مبنای نصب است.
- `PwaProvider`: ثبت `/sw.js` یک ثانیه پس از load، رویداد نصب Chrome، وضعیت شبکه/standalone و به‌روزرسانی اختیاری. خطای ثبت worker مانع سایت یا اسکرول نمی‌شود.
- `public/sw.js`: worker کلاسیک و same-origin، بدون وابستگی خارجی. فقط `/offline.html`، آیکون ۱۹۲ و فونت Dana-Regular precache می‌شوند؛ JavaScriptهای Next، نقشه و تصاویر منو در Cache Storage ذخیره نمی‌شوند.
- navigation با network/no-store اجرا می‌شود. شکست شبکه یا HTTP 5xx، صفحه عمومی قطع اتصال با status 503 و noindex/no-store می‌دهد؛ URL کافه یا جست‌وجوی اصلی حفظ می‌شود. ۴۰۴ و redirect ورود به همان شکل عبور می‌کنند.
- API، RSC، POST/PUT/DELETE و سایر درخواست‌ها توسط worker دستکاری، صف‌بندی یا بازپخش نمی‌شوند؛ نظر یا عملیات داده‌ای بعد از اتصال خودکار تکرار نمی‌شود.
- صفحه آفلاین حاوی قیمت/تخفیف/حساب نیست. اگر اینترنت در صفحه باز قطع شود، نوار هشدار تازگی نمایش داده می‌شود. PWA به معنی کارکرد کامل سایت بدون اینترنت نیست.
- این سیاست Cache Storage اپ است؛ کوکی نشست و ذخیره‌سازی معمول مرورگر همچنان برای ورود و قابلیت‌های سایت استفاده می‌شوند.
- نسخه worker فقط با درخواست صریح کاربر skipWaiting می‌کند. تب‌های دیگر خودکار reload نمی‌شوند تا فرم‌ها از دست نروند. با بسته‌شدن تب‌های قدیمی هم نسخه منتظر می‌تواند فعال شود.
- `next.config.mjs`: worker با JavaScript MIME، no-store و Service-Worker-Allowed `/`؛ صفحه آفلاین noindex/no-store. `/install` صفحه ابزار با noindex/follow است و به Sitemap اضافه نمی‌شود.

## نگهداری

در هر انتشار جدید، VERSION داخل sw.js را افزایش بده تا مرورگر نسخهٔ جدید worker را تشخیص دهد و نوار به‌روزرسانی نمایش داده شود؛ به‌ویژه هنگام تغییر offline.html، دارایی‌های precache یا سیاست کش این کار الزامی است. تشخیص نسخه به تغییر بایت‌های worker وابسته است، نه صرفاً اجرای npm run build. صفحات پویا در هیچ‌کدام از نسخه‌ها داخل worker کش نمی‌شوند. کش‌های قدیمی فقط با پیشوند `kucafe-pwa-` پاک می‌شوند؛ کش اپ دیگری حذف نمی‌شود.

فایل sw.js را با ۴۰۴ یا redirect به login جایگزین نکن: مرورگرها ممکن است worker قبلی را نگه دارند. پس از rollback برنامه نیز endpoint صحیح worker باید بماند. چون HTML/قیمت/پنل در worker کش نشده‌اند، بازگشت بیلد برنامه نیازمند دستکاری دیتابیس یا داده کاربر نیست.

این نسخه اپ بومی یا انتشار فروشگاهی نیست. Push notification، دانلود منوی آفلاین و GPS پس‌زمینه در این مرحله پیاده‌سازی نشده‌اند.

## نتیجه تست و انتشار

بیلد تأییدشده: `QJo1Wlm5x8KUWc8TqwjCx`، تاریخ ۱۸ سپتامبر ۲۰۲۶.

- `npm test`: هر ۳۳۶ تست موفق؛ شامل تشخیص دستگاه و سیاست‌های worker.
- `npm run typecheck` و `npm run build`: موفق.
- `git diff --check` روی فایل‌های موجود تغییرکرده: موفق. پروژه فرمان/config مستقل ESLint ندارد؛ اجرای Lint مستقل ادعا نمی‌شود.
- `scripts/pwa-smoke.ts`: روی بیلد محلی، عرض‌های ۳۲۰، ۳۹۰، ۴۳۰ و ۱۴۴۰، آیکون‌ها، MIME، نبود overflow و نبود خطای Runtime تأیید شد.
- Chromium با پروفایل عادی، نه Incognito: manifest توسط خود مرورگر خوانده شد و `Page.getInstallabilityErrors` خطایی گزارش نکرد. قبول پنجرهٔ نصب سیستم‌عامل و نصب WebAPK واقعی آزمایش نشده؛ اتصال دکمه نصب به رویداد مرورگر جداگانه با رویداد شبیه‌سازی‌شده آزمایش شد.
- قطع واقعی شبکهٔ صفحه و worker، fallback با HTTP 503، حفظ URL و تلاش مجدد پس از اتصال موفق بودند. فقط سه دارایی مجاز در Cache Storage اپ وجود داشتند.
- چرخهٔ worker واقعی با دو تب: به‌روزرسانی منتظر، لغو تأیید و حفظ فرم، فعال‌سازی صریح و reload فقط همان تب، حفظ فرم تب دیگر، حذف فقط کش نسخهٔ قدیمی خود اپ، خواندن API تازه، عدم کش HTML خصوصی و عدم بازپخش POST آفلاین تأیید شدند. داده‌های این سناریو fixture محلی بودند، نه حساب یا عملیات واقعی سایت.

تست آیفون فیزیکی/Safari واقعی بدون دستگاه مک/آیفون در این محیط ادعا نمی‌شود؛ راهنمای iOS با User-Agent و حالت standalone شبیه‌سازی و کارکرد مرورگر با Chromium بررسی شد. Safe Area واقعی و ظاهر پنجره نصب روی گوشی همچنان باید توسط مالک روی دستگاه بررسی شوند.

## انتشار عمومی

- نسخهٔ تأییدشده روی `https://kucafe.ir` و `https://dev.kucafe.ir` منتشر شد؛ BUILD_ID هر دو همان مقدار بالاست.
- تمام سناریوهای UI/قطع شبکه/تلاش مجدد/حالت standalone و بررسی نصب‌پذیری پروفایل عادی Chromium روی **هر دو دامنهٔ HTTPS عمومی** موفق بودند؛ در چهار عرض بررسی‌شده overflow افقی یا خطای Runtime صفحه نصب دیده نشد. اسکرین‌شات‌های مرجع در `/opt/kucafe/var/qa/pwa/` نگهداری می‌شوند.
- `curl -I` عمومی: `/sw.js` با HTTP 200، `text/javascript; charset=utf-8`، `Cache-Control: no-store, max-age=0` و `Service-Worker-Allowed: /`؛ manifest با HTTP 200 و `application/manifest+json`. Worker فعلی MapLibre در هر دو دامنه نیز HTTP 200 و JavaScript MIME صحیح دارد.
- `www.kucafe.ir/install` با HTTP 308 به `https://kucafe.ir/install` می‌رود؛ نصب اصلی را از دامنه بدون www انجام بده.
- بررسی بازگشتی عمومی در هر دو دامنه: خانه، جست‌وجوی «پاستا راموز»، صفحه راموز، ورود و ثبت‌نام HTTP 200؛ پنل کافه بدون نشست HTTP 307 به ورود. هر ۲۷ فایل CSS/JS ارجاع‌شده در صفحات بررسی‌شدهٔ هر دامنه HTTP 200 داشتند. این بررسی تأیید صحت کامل نتایج جست‌وجو یا عملیات پشت ورود نیست.
- انتشار با کپی فقط فایل‌های فهرست `docs/PWA_FILES.txt` و بیلد آزمایش‌شده انجام شد؛ `.env`، حساب‌ها، منوها، قیمت‌ها و schema دیتابیس تغییر نکردند و Migration/اسکرپ اجرا نشد. بازدیدها ممکن است به‌صورت معمول توسط Analytics سایت ثبت شده باشند.
- سرویس اصلی با PM2 از `/var/www/kucafe` و dev با `kucafe-dev` راه‌اندازی مجدد شدند. یک پاسخ موقت 503 پیش از آماده‌شدن مجدد فرآیند اصلی دیده شد؛ پس از Ready بررسی‌های عمومی موفق بودند. این نوع reload تک‌فرآیندی، انتشار با تضمین صفر قطعی نیست.
- سرور QA موقت localhost:9096 پس از پذیرش خاموش شد؛ فقط سرویس‌های اصلی 3000 و dev:9091 باقی ماندند.

نسخهٔ منبع قبلی فایل‌های موجود: `/var/backups/kucafe/pwa-source-before-20260918.tar.gz`.
بیلد قبل از PWA در اصلی: `/var/www/kucafe/.next-before-pwa-20260918`؛ در dev: `/opt/kucafe/.next-before-pwa-20260918`؛ BUILD_ID قبلی `n2u8SGw7xHSOmacrR6gax` است. این‌ها پشتیبان مخصوص انتشارند، نه جایگزین بکاپ کامل سایت/دیتابیس. فایل‌های جدید PWA پیش از این انتشار وجود نداشتند؛ هنگام بازگشت worker فعال مرورگر را نیز مطابق بخش نگهداری در نظر بگیر.

## کارهای باقی‌مانده برای مالک

1. روی یک گوشی اندروید واقعی، صفحه نصب اصلی را در Chrome باز کن، نصب را تأیید کن و از آیکون وارد سایت شو؛ ورود با همان حساب و بازشدن صفحه کافه را بررسی کن.
2. روی آیفون واقعی، مراحل Safari بالا را انجام بده و بازشدن اپ، Safe Area و ورود با همان حساب را بررسی کن. تست Safari واقعی قبلاً به درخواست مالک از دامنهٔ تست کنار گذاشته شده بود؛ این نسخه هم ادعای تست سخت‌افزاری آن ندارد.
3. برای انتشارهای بعدی VERSION worker را طبق بخش نگهداری افزایش بده؛ ذخیرهٔ فرم‌های پنل پیش از تأیید به‌روزرسانی ضروری است.

فایل این گزارش در `/var/www/html/KUCAFE_PWA_FA.md` نیز قرار دارد. اپ امکانات سایت را از همان Backend و حساب‌ها استفاده می‌کند؛ منو/قیمت/تخفیف آفلاین، Push و انتشار فروشگاهی در این مرحله ارائه نشده‌اند.
