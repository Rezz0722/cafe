# اصلاح منوی موبایل — ۲۰۲۶/۰۹/۲۶

## محدوده و معماری

منو همچنان در `src/components/cafe/MenuBrowser.tsx` و CSS Module موجود پیاده‌سازی شده است. انتخاب دسته، جست‌وجوی deferred، صفحه‌بندی آیتم‌ها و History API فعلی حفظ شدند. دیتابیس، پنل مدیریت، مسیر صفحات و وابستگی‌های پروژه تغییر نکرده‌اند.

مهارت‌های mobile-native از UI Skills، fixing-accessibility، fixing-motion-performance و playwright-cli برای رفتار بومی اسکرول، پنجره‌ها و آزمون مرورگر استفاده شدند.

## علت‌های تأییدشده و اصلاحات

- گرید موبایل صریحاً تک‌ستونه بود و ارتفاع حداقل کارت با `50dvh` تعیین می‌شد. اکنون دو ستون، تصویر ثابت ۴:۳ و متن مستقل زیر تصویر دارد؛ کل کارت یک دکمه است. نام فارسی و انگلیسی، شمارش، نام طولانی و حالت انتخاب‌شده حفظ شده‌اند.
- هدر دستهٔ انتخاب‌شده حداقل ۲۲۰ پیکسل ارتفاع داشت. در موبایل تصویر و تزئینات تکراری آن حذف و عنوان/تعداد در هدر متنی کوچک نمایش داده می‌شوند. تصویر دسکتاپ باقی است؛ منبع تصویر مخفی در موبایل نیز بارگیری شبکه‌ای ندارد.
- دو `scrollIntoView` متوالی برای نتایج و دکمهٔ دسته، والدهای مشترک را جابه‌جا می‌کردند. اکنون فقط بدنهٔ منو و خود نوار دسته‌ها جداگانه اسکرول می‌شوند. نوار بومی است؛ snapping حذف شده و حرکت لمس در ref نگه‌داری می‌شود، نه state. حرکت بیشتر از آستانه، کلیک ناشی از کشیدن را خنثی می‌کند و مانع اسکرول بومی نمی‌شود.
- شمارش آیتم در نوار قبلاً ردیف اضافه ایجاد می‌کرد و قاعدهٔ دسکتاپ تعداد خطوط عنوان را بازنویسی می‌کرد. شمارش در همان ردیف و عنوان حداکثر دوخطی شده است. sticky روی والد مناسب اعمال شده است.
- قفل بدنه قبلاً هنگام جابه‌جایی بین پنجره‌ها دوباره اعمال می‌شد و فوکوس بدون `preventScroll` حرکت می‌کرد. قفل اکنون مستقل از پنجرهٔ داخلی است؛ فوکوس، Escape، Tab، بازگشت به کنترل فراخوان و inert بودن پنل پشت پنجره بررسی شده‌اند. عبور از breakpoint هنگام چرخش/تغییر اندازه، قفل دسکتاپ را آزاد می‌کند.
- viewport با `100dvh` و fallback، safe-area چهارسویه، هدر غیرقابل‌فشرده‌شدن و یک ناحیهٔ اسکرول داخلی تنظیم شده است.
- ۲۴ لایهٔ blur روی دکمه‌های کارت‌های موبایل نمونه حذف شدند. هیچ کتابخانهٔ انیمیشن یا scroll handler پیوسته اضافه نشده است.
- تصاویر نسبت ثابت، `object-fit: cover`، lazy loading و decode غیرهم‌زمان دارند. در نمایشگر پرتراکم برای تصویر اختصاصی، فایل full موجود انتخاب می‌شود. تابع `categoryArtworkFull` دیگر به URL آمادهٔ `.full.webp` پسوند تکراری اضافه نمی‌کند.

## مقایسهٔ اندازه‌گیری‌شده

نمونه: منوی راموز، ۲۴ دسته، Chromium با viewport برابر ۳۶۰×۷۳۲، دستهٔ سوم و فونت بارگیری‌شده. پیش از تغییر روی نسخهٔ عمومی و پس از تغییر روی نسخهٔ محلی اندازه‌گیری شد؛ اعداد CSS pixel هستند.

این مقایسه به معنی بهبود عددی FPS نیست. در پروفایل ژست عمودی نسخهٔ قدیمی فقط یک Layout و صفر RecalcStyle دیده شد؛ شواهدی برای رندر مکرر کل صفحه هنگام اسکرول به دست نیامد. مشکلات اصلیِ تأییدشده، ابعاد بیش از حد، جابه‌جایی متداخل والدها و تزئینات پرهزینه بودند. مقادیر CDP پس از اصلاح در گزارش JSON ذخیره می‌شوند؛ یک اجرای dev پس از بارگیری فونت‌ها، صفر Layout در ژست عمودی و یک Layout در ژست افقی داشت. این اندازه‌گیری شبیه‌ساز، تضمین FPS روی سخت‌افزار ضعیف نیست.

## محدودیت‌ها و انتشار

بعضی تصاویر full راموز فقط ۴۶۲ پیکسل عرض دارند (تصویر قهوهٔ بررسی‌شده ۶۰۰ پیکسل). این محدودیتِ منبع است و برای نمایشگرهای 3× به‌خصوص پس از crop، وضوح کامل تضمین نمی‌شود. هیچ تصویر مصنوعیِ بزرگ‌شده‌ای به‌عنوان منبع باکیفیت معرفی نشده و فایل‌ها یا داده‌های کافه‌ها تغییر نکرده‌اند.

تست روی Chromium دسکتاپ با شبیه‌سازی موبایل/لمس انجام شده؛ گوشی واقعی اندرویدی، نوار مرورگر دستگاه واقعی، TalkBack و Safari/iOS آزمایش نشده‌اند. safe-area در CSS لحاظ شده، ولی بریدگی و نوار سیستم روی سخت‌افزار واقعی باید بازبینی شوند.
