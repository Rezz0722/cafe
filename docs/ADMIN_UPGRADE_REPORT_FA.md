# نتیجه اصلاح پنل مدیریت KuCafe

وضعیت: اصلاحات این گزارش در ۱۹ سپتامبر ۲۰۲۶ روی `https://kucafe.ir` و `https://dev.kucafe.ir` منتشر و بررسی شدند.

شناسهٔ نسخهٔ مشترک: `xqdBLDde44IigwYR5p-rH`.

## نتیجهٔ آزمون

- Build، Typecheck و Lint موفق؛ ۳۴۷ تست واحد و ۳۱ بررسی یکپارچهٔ دیتابیس پاس شدند.
- ۶۰ بررسی مرورگری با دادهٔ آزمایشی، شامل حفظ ورودی در خطا، حفاظت مستقل دو فرم، تغییر و بازگردانی دقیق قیمت، ساخت/ویرایش/توقف پیشنهاد، آرشیو/بازیابی کافه و رد فرم دستکاری‌شدهٔ مالک پاس شدند.
- پس از انتشار، ۹۶ بررسی خواندنی روی هر دامنه، مجموعاً ۱۹۲ بررسی، در عرض‌های ۳۲۰، ۳۹۰ و ۱۴۴۰ پاس شد. مسیرهای اصلی، جست‌وجو، کافه، ورود و ثبت‌نام، تب‌های مدیریت و منوی راموز بررسی شدند؛ خطای جدید Runtime، درخواست GET ناموفق یا overflow افقی در این سناریوها دیده نشد.
- تب فعال موبایل در محدودهٔ قابل مشاهده قرار می‌گیرد؛ اسکرین‌شات اصلی و dev بررسی شد.
- نقشه و Marker در مرورگر نمایش داده شدند؛ چهار فایل MapLibre با پسوند `.mjs` در اصلی MIME جاوااسکریپت دارند. اسکرول قفل نشد.
- گزارش انتخابی اسکرپ در تولید با GET بررسی شد: جمع‌بندی و دانلود یک کافه صحیح و انتخاب نامعتبر رد شد. هیچ اسکرپ یا apply واقعی اجرا نشد.
- فایل‌های fingerprint نسخهٔ قبل حفظ شدند و نمونه‌های قبلی در هر دو دامنه پاسخ ۲۰۰ دادند. `www` به دامنهٔ اصلی ۳۰۸ می‌دهد.
- بررسی وابستگی‌ها با `npm audit`: صفر آسیب‌پذیری گزارش‌شده. Playwright به نسخهٔ اصلاح‌شده ارتقا یافت و مرورگر موردنیاز آن نصب شد.
- پس از تست، تعداد کافه‌های آزمایشی باقی‌مانده صفر بود؛ سرویس‌های QA لوکال متوقف شدند.

این نتایج، سناریوهای اجراشده را تأیید می‌کنند؛ ادعای تست روی همهٔ دستگاه‌های فیزیکی یا اجرای دوبارهٔ اسکرپ واقعی نیستند.

## تغییرات

- حفاظت از پیش‌نویس هر فرم، جلوگیری از ارسال تکراری و حفظ ورودی در خطا.
- ذخیره تراکنشی اطلاعات، ساعت، امکانات و تنظیمات؛ کنترل نسخه زیر قفل دیتابیس.
- صف تأیید پاسخ کافه‌دار و نمایش وضعیت انتشار پاسخ.
- منوی همان شعبه به‌عنوان پیش‌فرض؛ جداسازی داده‌های شعبه‌های دیگر بدون حذف.
- جست‌وجو، فیلتر و صفحه‌بندی سرور با ۲۵ رکورد؛ حذف سقف پنهان کاربران و مجموعه‌ها.
- تب مشتریان و تخفیف؛ مدیریت پیشنهاد، کدهای صادرشده و مصرف؛ حفظ رضایت و Scope شماره‌ها.
- قیمت گروهی انتخابی، پیش‌نمایش معتبر، snapshot کامل و بازگردانی با کنترل تغییرات بعدی.
- مدیریت نوع مجموعه، محله، برند و شعبه با مجوز مناسب و انتخاب موقعیت روی نقشه.
- گزارش کامل و انتخابی اسکرپ، تازه‌سازی غیرمسدودکننده و تاریخچهٔ اجرا.
- تاریخچهٔ قابل مشاهده با پاک‌سازی اطلاعات حساس، آرشیو قابل بازیابی و دورهٔ هفت‌روزه قبل از حذف دائمی.
- برچسب‌ها، پیام نتیجه کنار فرم، تاریخ پایان شمسی و کنترل‌های مناسب لمس.

## حفاظت داده و انتشار

پشتیبان پیش از کار: `/var/backups/kucafe/admin-upgrade-20260918/`، خصوصی و خارج از مسیر وب. فایل‌های کد و dump دیتابیس فشرده و صحت فایل فشرده بررسی شده‌اند.

پشتیبان تازهٔ پیش از انتشار: `database-before-publish.sql.gz` و `production-source-before-publish.tar.gz` در همان مسیر. نسخهٔ قبلی Build در `.next-before-admin-upgrade-20260919` در هر پروژه باقی است؛ وابستگی‌های قبلی اصلی در `/var/www/kucafe/.node_modules-before-admin-upgrade-20260919` نگهداری شدند. فهرست فایل‌های انتشار در `docs/ADMIN_UPGRADE_FILES.txt` است.

فرایند اصلی با `npm run reload:safe` و dev با سرویس خودش راه‌اندازی مجدد شد. وضعیت گزارش آمادهٔ اصلی و شناسهٔ اجرای آن حفظ شد. برای این انتشار نیازی به بازگردانی دیتابیس نبود.

هیچ migration یا تغییر schema انجام نشده است. تست‌های نوشتنی فقط رکوردهای UUID آزمایشی را تغییر می‌دهند و در پایان پاک یا rollback می‌کنند. اسکرپ و اعمال گزارش واقعی برای تست اجرا نمی‌شوند.

## محدودیت‌های واقعی

- گزارش‌های قدیمی اسکرپ قبلاً سقف ۱۰۰۰ جزئیات داشتند؛ جزئیات حذف‌شده از آن فایل‌ها قابل بازسازی نیست. گزارش‌های جدید بدون این سقف ذخیره می‌شوند؛ رابط برای سبک‌ماندن، نمونه نشان می‌دهد و خروجی کامل مجاز است.
- اجراهای قدیمی بدون `job.json` وضعیت نهایی قابل‌اثبات ندارند؛ در تاریخچه «قدیمی — وضعیت ثبت نشده» نشان داده می‌شوند.
- پیشنهاد دارای کد قابل‌ویرایش نیست تا شرایط مشتری بعد از صدور عوض نشود؛ توقف و ساخت پیشنهاد جدید مجاز است.
- قیمت‌های گروهی قدیمی که snapshot نداشته‌اند قابل بازگردانی دقیق از پنل نیستند؛ قابلیت جدید فقط برای عملیات ثبت‌شده با snapshot معتبر است.
- ارسال گروهی به پنل اعضای رضایت‌داده‌شده انجام می‌شود؛ پیامک ارسال نمی‌کند.
- بازیابی آرشیو، بازیابی کامل دیتابیس نیست. برای حذف دائمی باید از بکاپ مناسب استفاده شود؛ بکاپ قدیمی را روی دیتابیس دارای فعالیت جدید بدون بررسی بازگردانی نکنید.
- تاریخ شمسی از ورودی متنی اعتبارسنجی‌شده استفاده می‌کند، نه تقویم تصویری.
- تست Safari مطابق درخواست قبلی انجام نشده؛ تست Chrome با Chromium دسکتاپ و شبیه‌سازی اندازه و لمس موبایل است، نه گوشی فیزیکی.
- آپلود موجود امن و دارای حالت انتظار/خطاست؛ آپلود resumable و درصد واقعی ارسال فایل هنوز پیاده نشده‌اند.
- صف تأیید پاسخ در کد، رندر و منطق وضعیت بررسی شد؛ تأیید/رد از مرورگر برای پاسخ واقعی مشتری اجرا نشد.

## اجرای مجدد تست‌ها

```bash
cd /opt/kucafe
npm run lint
npm run typecheck
npm test
npm run admin:upgrade:smoke
```

تست نوشتنی مرورگری فقط روی QA لوکال اجرا شود، نه سرویس اصلی یا dev زنده:

```bash
NEXT_DIST_DIR=.next-admin-upgrade-qa npm run build:next
NEXT_DIST_DIR=.next-admin-upgrade-qa npm run start -- -H 127.0.0.1 -p 9096
# ترمینال جدا؛ فقط رکوردهای آزمایشی UUID ساخته و پاک می‌شوند:
QA_BASE_URL=http://127.0.0.1:9096 node --import tsx --conditions=react-server scripts/admin-upgrade-ui-smoke.ts
```

بررسی انتشار فقط خواندنی است و از نشست فعال مدیر استفاده می‌کند؛ حساب یا نشست جدید نمی‌سازد:

```bash
node --import tsx --conditions=react-server scripts/admin-upgrade-live-smoke.ts https://kucafe.ir https://dev.kucafe.ir
```

اسکرین‌شات‌ها در `var/qa/` خصوصی‌اند و ممکن است اطلاعات مدیریتی داشته باشند؛ عمومی‌شان نکنید.
