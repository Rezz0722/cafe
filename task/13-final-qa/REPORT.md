## چهار باگ که در همین تسک پیدا و رفع شد

### ۱. build با segfault می‌ترکید

```
Next.js build worker exited with code: 3221225477
```

کد `3221225477` = `0xC0000005` = نقض دسترسی حافظه. این ماشین **۴ گیگابایت
RAM** دارد و MySQL هم رویش است؛ workerهای موازیِ Next جمعاً از حافظه‌ی
فیزیکی رد می‌شدند. (خودِ من هم با `--max-old-space-size=4096` که از RAM
فیزیکی بزرگ‌تر بود، مشکل را بدتر کرده بودم.)

رفع: `workerThreads: false` و `cpus: 1` در `next.config.mjs` — تک‌فرآیندی،
کندتر ولی قابل اتمام. با توضیح اینکه روی سرور با حافظه‌ی بیشتر می‌شود
برداشتشان.

### ۲. `drizzle-kit push` ایندکس‌های FULLTEXT را بی‌صدا انداخته بود

`db:smoke` با `ER_FT_MATCHING_KEY_NOT_FOUND` شکست. علتش این بود که وقتی
enum را برای افزودن `shop` عوض کردم و `drizzle-kit push` زدم، هر سه ایندکس
FULLTEXT رفتند — چون در `schema.ts` تعریف نشده‌اند (drizzle آن‌ها را تولید
نمی‌کند).

این یک **خرابیِ دیرآشکار** است: سایت بالا می‌آید و همه‌چیز کار می‌کند تا
لحظه‌ای که کسی جست‌وجو کند.

دو رفع، تا دیگر تکرار نشود:
1. `npm run db:push` حالا خودش `db:extras` را پشت سرش اجرا می‌کند.
2. `npm run db:verify` اضافه شد و وجود هر سه ایندکس را بررسی می‌کند.

### ۳. شمارش نتایج، فیلترها را نادیده می‌گرفت

بعد از رفع FULLTEXT، جست‌وجوی «مجنون» یک کارت نشان می‌داد ولی زیرش می‌نوشت
**«۳۲۶ مجموعه»** — و صفحه‌بندی هم از همان عددِ غلط ساخته می‌شد.

علت: `countPlaces` و `listPlaceCards` شرط‌هایشان را **جدا** می‌ساختند و
اولی فقط `publishedOnly`، `districtId` و `mappableOnly` را می‌فهمید. فیلتر
متن، facet، دیش، رده و سقف قیمت در شمارش اثری نداشتند.

رفع: `buildPlaceConditions` مشترک. حالا هیچ‌وقت از هم نمی‌افتند:

| فیلتر | شمارش | کارت در صفحه |
| --- | --- | --- |
| نام «مجنون» | ۱ | ۱ |
| پاستا | ۹۴ | ۲۴ |
| پاستا + قلیان | ۵ | ۵ |
| رده‌ی ارزان | ۱۰۳ | ۲۴ |
| تا ۲۰۰ هزار | ۱۰۱ | ۲۴ |
| محله وکیل‌آباد | ۳۹ | ۲۴ |
| بدون فیلتر | ۳۲۶ | ۲۴ |

### ۴. انحراف سبک کد

یک بار `npx prettier --write` را بدون فایل تنظیمات روی `queries.ts` زدم و آن
فایل به سبک «نقطه‌ویرگول + گیومه‌ی دوتایی» رفت، در حالی که کل پروژه بدون
نقطه‌ویرگول و با گیومه‌ی یکتایی است.

رفع: `.prettierrc` با سبک خودِ پروژه اضافه شد و فایل به حالت اصلی برگشت.
حالا هر اجرای prettier همان سبک را حفظ می‌کند.

## بررسی آفلاین‌بودن — خودکار در هر اجرا

`pages-smoke.mjs` فقط دنبال «کد ۲۰۰» نیست؛ دو چیز را **ممنوع** هم می‌کند:

```
✓ /cafe/jan-majnoon-lounge   نباید cdn.topmenumarket.com داشته باشد
✓ /api/map/style?theme=light نباید https:// داشته باشد
```

یعنی اگر روزی کسی یک تصویر یا تایلِ CDN وارد کد کند، تست می‌شکند. تصویر و
نقشه هر دو از سرور خودمان می‌آیند:

```
image → 200 image/webp                      /media/item/2e/2e1a34….webp
tile  → 200 application/vnd.mapbox-vector-tile
```
