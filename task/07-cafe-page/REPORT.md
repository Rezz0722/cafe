# تسک ۰۷ — ریدیزاین صفحه‌ی کافه ✅

## چرا ریدیزاین لازم بود

چیدمان قبلی برای داده‌ی نمونه ساخته شده بود: چند تگ، یک بازه‌ی قیمت، منوی
چندآیتمی. داده‌ی واقعی چیز دیگری است:

| واقعیت داده | اثرش روی چیدمان قبلی |
| --- | --- |
| تا **۲۸۷ آیتم منو** در **۳۰ دسته** | فهرست پشت‌سرهم غیرقابل استفاده |
| ۵۶٪ آیتم‌ها عکس دارند | بارگذاری یک‌جا، صفحه را می‌خواباند |
| ساعت کاری با **شیفت شکسته** | ساعت ۱۸ رستوران دوشیفته «باز» نشان داده می‌شد |
| چند شماره تلفن (۹۲ مکان) | فقط یکی نمایش داده می‌شد |
| ۷۳ مکان **بدون مختصات** | دکمه‌ی مسیریابیِ بی‌کار |
| ۹۲۸ آیتم **بدون قیمت معتبر** | «۰ تومان» نمایش داده می‌شد |

## چیدمان جدید — بر ترتیب سؤال‌های کاربر

```
۱. الان باز است؟   → نشانِ وضعیت، اولین چیز بعد از نام
۲. چطور بروم؟      → دکمه‌ی مسیریابی، بلافاصله زیر نام
۳. چه دارد و چند؟  → منو با جست‌وجو و پرش دسته
۴. کجاست؟          → نقشه‌ی آفلاین با پین
۵. چه کسی رفته؟    → نظرها
```

روی موبایل ستون کنار (نقشه + ساعت) با `order: -1` **قبل** از منو می‌آید:
کاربر موبایل معمولاً وسط شهر ایستاده و اول می‌خواهد بداند باز است و کجاست.

## اجزای ساخته‌شده

### `MenuBrowser` — قلب صفحه

سه چیز منوی ۲۸۷ آیتمی را قابل استفاده می‌کند:

1. **نوار دسته‌ی چسبان** — پرش مستقیم، همیشه در دسترس
2. **جست‌وجوی درون‌منو** — «لاته» بنویس، فوری پیدا شود. در کلاینت انجام
   می‌شود چون کل منو از قبل در HTML است؛ بدون رفت‌وبرگشت شبکه.
   `useDeferredValue` تایپ‌کردن را روان نگه می‌دارد.
3. **تصویر با بارگذاری تنبل** + `width`/`height` از دیتابیس — بدون ابعاد،
   صفحه با رسیدن هر تصویر می‌پرد و در ۲۸۷ آیتم غیرقابل استفاده می‌شود.

به‌علاوه: فیلتر «فقط با عکس»، نمای بزرگ (lightbox) با نسخه‌ی ۱۰۰۰px،
نشان آیتم ویژه، و «موجود نیست».

### `openNow.ts` — «الان باز است؟» با شیفت

ماژول جدید، چون `openState.ts` قبلی فرض می‌کرد هر روز یک بازه دارد. سه
تله‌ای که بسته شد:

1. **منطقه‌ی زمانی** — «الان» با `Intl` به وقت تهران حساب می‌شود، نه با افست
   ثابت. سرور UTC، بدون این، همه‌ی کافه‌ها را نیمه‌شب «باز» نشان می‌داد.
2. **گذر از نیمه‌شب** — کافه‌ی ۱۶:۰۰ تا ۰۰:۳۰ ساعت ۰۰:۱۵ *بامداد روز بعد*
   باز است، یعنی باید شیفتِ **دیروز** را هم نگاه کرد.
3. **نامشخص ≠ تعطیل** — روزی که در داده نیست یعنی نمی‌دانیم. «تعطیل» گفتن
   برایش دروغ است.

۲۰ تست، همه سبز.

### `DirectionsBar`

نشان و گوگل مپس همیشه دیده می‌شوند؛ بلد، ویز، OSM، `geo:` و کپی مختصات در
منوی جمع‌شده. نمایش هر پنج سرویس به‌صورت دکمه، مهم‌ترین کار صفحه را در شلوغی
گم می‌کرد.

**بدون مختصات، دکمه‌ی مسیریابی ساخته نمی‌شود** — به‌جایش آدرس متنی. دکمه‌ای
که هیچ‌جا نمی‌برد بدتر از نبودنش است.

### بخش‌های داده‌محور

- **«اینجا چه پیدا می‌کنید»** — از `place_facet`: «پاستا · ۱۲ آیتم · از ۳۲۰
  هزار». عددِ اثبات‌پذیر، نه برچسبِ دستی.
- **«ارزان‌تر از میانگین شهر»** — دیش‌هایی که اینجا ≥۲۰٪ زیر میانه‌ی شهری‌اند،
  با **هر دو عدد** کنار هم تا کاربر خودش قضاوت کند.
- **نوار آمار** — میانگین قیمت، بازه، رده، تعداد آیتم، امتیاز.
- **یادداشت شفافیت** — اگر قیمت‌های مجموعه از «هزار تومان» تبدیل شده‌اند،
  همان‌جا نوشته می‌شود. پنهان‌کردنش یعنی اگر اشتباه کرده باشیم، کاربر هیچ
  راهی برای فهمیدن ندارد.

### `PlaceJsonLd` بازنویسی شد

- props شکل خودش را دارد، نه `PlaceDetail` — تا صفحه‌ی محله برای رندر
  JSON-LD مجبور نباشد کل منو را بخواند.
- **شیفت شکسته**: هر بازه یک `OpeningHoursSpecification` جدا. ادغامشان به
  گوگل می‌گفت مکان ساعت ۱۸ باز است، که نیست.
- سقف ۱۲ دسته × ۱۵ آیتم: منوی ۲۸۷ آیتمی، JSON-LD را بزرگ‌تر از خودِ HTML
  می‌کرد.
- فقط آیتم‌های قیمت‌دار — `Offer` بدون `price` نامعتبر است.
- قیمت ×۱۰ می‌شود چون واحد `IRR` (ریال) است و داده‌ی ما تومان.

## چطور تست شد

سرور توسعه بالا آمد و صفحات واقعی با `curl` بررسی شدند:

| مورد آزمایش | نتیجه |
| --- | --- |
| `jan-majnoon-lounge` (۱۵۲ آیتم) | HTTP ۲۰۰ · ۳۰۶KB · نام، منو، تصویر لوکال، JSON-LD، قیمت ۹۹۰٬۰۰۰ ✓ |
| `blackhorse-hall` (**۲۸۷ آیتم** — بزرگ‌ترین منو) | HTTP ۲۰۰ · ۶۰۵KB · **۱٬۹۵۲ms** · جست‌وجوی منو حاضر ✓ |
| `darvishirosehotel` (**بدون مختصات**) | HTTP ۲۰۰ · ۵۸۳ms · پیام صادق، بدون دکمه‌ی مسیریابیِ بی‌کار ✓ |
| `aria-group` (**بدون منو**) | HTTP ۲۰۰ · ۶۰۷ms · پیام «منو ثبت نشده» ✓ |
| لینک نشان و گوگل در HTML سرور | `neshan.org/maps/routing` و `google.com/maps/dir` ✓ |
| تصویر لوکال | `/media/item/…` ✓ — هیچ ارجاعی به CDN بیرونی |
