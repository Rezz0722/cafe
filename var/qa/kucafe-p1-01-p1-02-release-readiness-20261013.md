## Migration، Production و ریسک

- `0015` فقط ستون `menu_section.source_name` و دو جدول Override را افزوده؛ `0016` فقط `place.last_source_sync_at` را افزوده و مقدار تاریخی را تنها برای `source='import'` + `source_id` + `last_verified_at` غیرخالی و مقصد خالی Backfill می‌کند. دادهٔ موجود پاک یا خودکار «تأیید مالک» نمی‌شود. ترتیب در `scripts/apply-project-migrations.mjs` صحیح است.
- بررسی **فقط‌خواندنی** دیتابیس اصلی نشان داد `0015/0016` هنوز اعمال نشده‌اند. در لحظهٔ بررسی، ۴۲٬۶۱۱ آیتم منبع‌دار و **یک آیتم منبع‌دار با سه Audit ویرایش تاریخی پنل** وجود داشت. تاریخچهٔ آن باید پیش از اولین Sync پس از انتشار موردی بررسی شود؛ هیچ Override خودکاری برای آن ساخته نشد. وضعیت آخر TopMenu worker: `completed`، بدون اجرای فعال در Snapshot بررسی.
- دو سرویس app و TopMenu worker سالم بودند؛ دیسک حدود ۶٫۹ گیگابایت آزاد داشت. آخرین بکاپ DB موجود با `gzip -t` معتبر بود؛ در زمان انتشار **بکاپ تازه** و کنترل فضای دیسک لازم است.
- Rollback پیش‌فرض: نسخهٔ پیشین **app و worker با هم** بازگردد و ستون‌ها/جدول‌های افزایشی حفظ شوند. فایل‌های `.rollback.sql` صرفاً گزینهٔ اضطراری پس از Export دادهٔ Override و زمان Sync هستند؛ اجرای پیش‌فرض آن‌ها ممنوع است. نسخهٔ قبلی برنامه ستون‌های افزوده را نادیده می‌گیرد. رشد رتبه/ایندکس گوگل یا رفتار Production پس از انتشار، در این مرحله ادعا نمی‌شود.

## چک‌لیست دقیق انتشار — فقط پس از مجوز صریح مالک

1. در GitHub سبز بودن CI و Head همان PR را تأیید؛ وضعیت صف TopMenu را دوباره بررسی و تا پایان Gate تاریخی هر Apply را متوقف کنید. مورد تاریخی را با Audit/مقدار فعلی/منبع مقایسه و دربارهٔ فیلدهای واقعاً ویرایش‌شده تصمیم انسانی ثبت کنید؛ از Backfill کورکورانهٔ Override پرهیز کنید.
2. فضای دیسک، Tag تصویر قبلی، سلامت app/worker و امکان Rollback را ثبت؛ بکاپ تازهٔ DB را پیش از Migration بسازید و صحت آن را کنترل کنید. Deploy فعلی خود نیز پیش از Migration بکاپ می‌سازد؛ از موجودبودن و معتبرماندن آن اطمینان بگیرید.
3. با **تأیید جداگانهٔ مالک برای Merge/Deploy**، PR #65 را Merge کنید. Deploy خودکار باید `0015`، `db:verify` و Healthcheck را انجام دهد؛ Schema، منوی عمومی، پنل، QR و Audit/worker را Smoke کنید. اگر شکست خورد، app+worker را به Tag پیشین برگردانید؛ Schema را حذف نکنید.
4. Base PR #66 را به `production` تغییر دهید؛ Diff و CI جدید را تأیید کنید. با **تأیید جداگانهٔ مالک برای Merge/Deploy دوم** PR #66 را Merge؛ Deploy باید `0016` را اجرا کند. Smoke همان مسیرها و تفکیک زمان منبع/قیمت در HTML واقعی Production را انجام دهید.
5. تنها پس از پایان بررسی مورد تاریخی، با Backup و انتخاب محدود، اولین TopMenu Preview/Apply را انجام دهید؛ تعارض‌ها، قیمت تومان/هزارگان، Audit، زمان‌ها و نبود بازنویسی مالک را بررسی کنید. اجرای گسترده بدون این Gate مجاز نیست.
