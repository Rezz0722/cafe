# KuCafe P1-02 — منشأ و زمان اطلاعات منو

تاریخ: ۱۲ اکتبر ۲۰۲۶ / ۲۰ مهر ۱۴۰۵ (تاریخ سرور). شاخه: `feat/p1-02-menu-provenance` بر پایهٔ P1-01. وضعیت: آمادهٔ بازبینی؛ **در Production منتشر نشده است**.

## مسئله و علت ریشه‌ای

`scripts/topmenu-sync.ts` زمان هر Apply را در `place.last_verified_at` می‌نوشت، با اینکه فقط دادهٔ خارجی همگام شده بود. صفحهٔ کافه در نبود `menu_item.price_updated_at` از همین زمان برای «آخرین به‌روزرسانی قیمت» استفاده می‌کرد. در نتیجه Sync تازه می‌توانست قیمتِ بی‌زمان یا قدیمی را تازه جلوه دهد. امتیاز تازگیِ مدل دامنه نیز زمان کلی مکان را برای فیلدهای بدون منشأ زمان‌دار جایگزین می‌کرد. `place.source` منشأ اولیهٔ رکورد است، نه منشأ همهٔ فیلدهای ویرایش‌شدهٔ بعدی.

## تغییرات

- Migration افزایشی `drizzle/0016_menu_source_sync_time.sql` ستون nullable `place.last_source_sync_at` را اضافه می‌کند. فقط رکوردهای دارای `source='import'` و `source_id` از زمان تاریخی `last_verified_at` به‌عنوان Sync قدیمی backfill می‌شوند؛ فیلد قدیمی دست‌نخورده می‌ماند و این داده «تأیید انسانی» شمرده نمی‌شود. Migration قابل‌تکرار است.
- Apply جدید TopMenu فقط `last_source_sync_at` را می‌نویسد؛ تغییر قیمت آیتم همچنان در `price_updated_at` ثبت می‌شود و قیمت محافظت‌شدهٔ بدون تغییر همان زمان قبلی را نگه می‌دارد.
- صفحهٔ عمومی زمان تغییر قیمت را فقط از آیتم‌های منو می‌گیرد؛ دیگر `last_verified_at` را fallback نمی‌کند. منشأ **اولیه**، جدیدترین تغییر ثبت‌شدهٔ قیمت، زمان Sync خارجی و هشدار قیمت‌های نیازمند بازبینی جدا نمایش داده می‌شوند. متن صفحهٔ اصلی هم میان تغییر قیمت و تأیید آن تفاوت می‌گذارد.
- امتیاز تازگی فیلدی فقط به `provenance.observedAt` همان فیلد تکیه می‌کند؛ زمان کلی مکان فیلد بدون شواهد را تازه نمی‌کند.
- مستند طراحی: `docs/KUCAFE_P1_02_PROVENANCE_FA.md`.

## ترتیب انتشار، ریسک و Rollback

P1-02 به P1-01 و Migration `0015` وابسته است؛ Merge/Deploy جداگانه و بدون تأیید مالک انجام نمی‌شود. پیش از انتشار: PR #65 و P1-02 بازبینی شوند، Backup معتبر گرفته شود، سپس Migration `0015` و `0016` پیش از اجرای کد جدید اعمال شود. Gate بررسی ویرایش‌های تاریخی مالک پیش از نخستین Sync همچنان برقرار است.

Rollback امن کد: نسخهٔ قبلی را بازگردانید و ستون جدید را نگه دارید تا زمان‌های Sync از دست نرود. فایل `drizzle/0016_menu_source_sync_time.rollback.sql` فقط پس از Export داده‌های این ستون قابل‌استفاده است. خطر باقی‌مانده: منشأ فیلدیِ کامل داده‌های قدیمی بدون Audit یا شواهد بیرونی قابل استنتاج نیست؛ هیچ رکورد قدیمی خودکار owner-verified نشده و تست روی Production انجام نشده است.

## وضعیت فاز و گام بعدی
